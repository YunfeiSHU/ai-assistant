# 06 · 非功能需求与可观测性

> 关联：需求 ID `REQ-NFR-*`；接缝 J3（trace 传递）见 [01-§7](./01-总体需求与范围.md)；降级细节见 [04-§9](./04-AI服务编排与网关.md)。

## 1. 性能（`REQ-NFR-001`）

| 指标 | P50 | P95 | 说明 |
| --- | --- | --- | --- |
| **网关自身额外延迟** | 8 ms | **30 ms** | 鉴权 + 配额 + 转发开销，**不含** AI 侧耗时 |
| 鉴权中间件 | 1 ms | 3 ms | JWT 验签 + `ver` 校验（至多一次 Redis 读） |
| 配额校验 + 预扣 | 2 ms | 5 ms | Redis 管道化 |
| 会话列表 `GET /conversations` | 30 ms | 80 ms | 单页 20 条，用户有 100 会话 |
| 消息分页 `GET .../messages` | 25 ms | 80 ms | 单页 20 条 |
| 消息落库（异步，不计入响应） | 5 ms | 20 ms | 含 `seq` 分配 |
| SSE 首帧转发延迟 | 3 ms | 15 ms | 从收到 AI 首帧到写出客户端 |
| SSE 单帧转发延迟 | 1 ms | 5 ms | token 转发 |
| 登录（含 Argon2id 校验） | 60 ms | 120 ms | 哈希成本固定，属 CPU 密集 |
| 上传转发吞吐 | — | — | 内网 ≥ 100 MB/s（流式 `io.Copy`） |

- 首 token 端到端 = AI 侧首 token + 网关增量（≤ 30 ms）。
- 所有 P50/P95 MUST 基于 ≥ 200 次采样。
- **MUST NOT** 在请求路径内做同步阻塞的 I/O 之外的 CPU 密集操作（如批量哈希）。

## 2. 容量与并发（`REQ-NFR-002/003`）

| 项 | 目标 |
| --- | --- |
| 单实例并发 SSE 连接 | ≥ 500 |
| 单实例非 AI 接口 QPS | ≥ 1000 |
| 单实例 AI 接口并发 | 受 AI 侧 `llm_max_concurrency` 约束；网关侧排队 ≤ 3 s |
| 单用户并发对话 | 5（配额 `concurrency`） |
| 用户规模 | ≤ 10 000（单库） |
| 单用户会话数 | ≤ 1 000 |
| 单会话消息数 | ≤ 20 000 |
| 单用户消息总量 | ≤ 200 000 |
| 请求体上限 | JSON 1 MB（`MAX_JSON_BODY_MB`）；multipart 由 `UPLOAD_MAX_MB` 约束 |
| 响应体上限 | 16 MB（`MAX_RESPONSE_MB`） |
| 内存占用 | 稳态 ≤ 256 MB（RSS），500 SSE 连接下 ≤ 512 MB |
| 长连接内存 | 每 SSE 连接 ≤ 64 KB（累积缓冲 MUST 有上限，见下） |

**流式累积缓冲的两条硬要求**：

1. 网关为了落库需要累积本次回答的完整文本，但 MUST 设置上限 `STREAM_ACCUMULATE_MAX_CHARS`（默认 64000）—— 超出后**继续透传给客户端但停止累积**，落库时截断并标 `status=partial`。防止恶意/异常的长回答把网关内存吃满。
2. `references` / `tool_calls` 的累积 MUST 有数量上限（默认各 200 条），超出丢弃并记 WARN。

## 3. 可靠性与可用性（`REQ-NFR-004/005`）

| 项 | 目标 |
| --- | --- |
| 可用性 | 硬依赖（MySQL/Redis）健康时 99.9%（月度）；AI 挂着也算可用（仅 AI 接口降级） |
| 优雅退出 | `SIGTERM` 后停止接受新连接，在途流式给 `GRACEFUL_SHUTDOWN_SECONDS`（20s），进程 ≤ 30s 退出 |
| 幂等 | 见 [02-§7](./02-接口规范与鉴权.md)，MUST 覆盖所有「重试会产生副作用」的接口 |
| 数据不丢 | 已返回 `done` 的对话 MUST 最终落库（失败则告警并可人工补偿） |
| 时钟 | 所有实例 MUST 用 NTP 同步（JWT 校验容差仅 30s） |

**优雅退出要求**：

```
SIGTERM
  ↓
① 停止接受新连接（HTTP server Shutdown）
② 等待在途请求完成，上限 GRACEFUL_SHUTDOWN_SECONDS
③ 超时的流式请求：先发 event: error(code=SERVICE_SHUTTING_DOWN) 或直接 done(finish_reason=canceled)，再落库 partial
④ 关闭 AI 连接池、DB 池、Redis 池
⑤ 退出
```

MUST NOT 直接 `os.Exit`（会丢掉已累积但未落库的回答）。

**就绪判断的取舍**：`/health/ready` **MUST NOT** 把 AI 可达性作为决定项 —— AI 挂掉时网关仍应继续接流量（历史、配额、会话管理都可用），若因此被 K8s 摘除会造成「AI 抖动 → 全体不可用」的错误放大。AI 状态只作为响应体中的信息字段上报。

## 4. 安全（`REQ-NFR-004` 之一）

### 4.1 认证与凭据

| 项 | 要求 |
| --- | --- |
| 密码存储 | Argon2id（`memory=64MB`、`iterations=3`、`parallelism=4`、`saltLen=16`、`keyLen=32`）；MUST NOT 用 MD5/SHA1/BCrypt-only |
| 密码比较 | MUST 使用库提供的恒定时间比较；对**不存在的用户**也 MUST 执行一次等价耗时的哈希校验（防用户枚举的时序侧信道） |
| 令牌传输 | 仅 HTTPS；MUST NOT 出现在 URL query；`Authorization` 头 MUST NOT 记入日志 |
| Refresh Token | 明文只在响应中出现一次；服务端只存 sha256；轮换 + 家族作废（见 [05-§2.2](./05-数据模型.md)） |
| 登录防爆破 | 单 IP 10 次/分钟 + 单账号 20 次/小时（后者按 `user_id` 或邮箱哈希计数）；连续 5 次失败后触发验证码（P2） |
| 密钥 | `JWT_SECRET` / `INTERNAL_SERVICE_TOKEN` MUST 由 Secret 注入；MUST NOT 硬编码、MUST NOT 入库、MUST NOT 出现在日志 |
| 密钥长度 | `JWT_SECRET` ≥ 32 字节随机；`INTERNAL_SERVICE_TOKEN` ≥ 32 字节随机 |

### 4.2 输入与输出安全

| 项 | 要求 |
| --- | --- |
| 注入 | 全部 SQL MUST 走参数化（GORM/`database/sql` 占位符）；MUST NOT 拼接用户输入 |
| 请求体大小 | MUST 用 `http.MaxBytesReader` 限制（JSON 1 MB），超限 `413`，MUST NOT 读到内存后判断 |
| 内容类型 | MUST 校验 `Content-Type`；`multipart` MUST 限制文件数与字段数（防 multipart bomb） |
| 响应头 | MUST 设置 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；若返回 HTML 则加 CSP（网关只返回 JSON，故 CSP 非必需） |
| CORS | MUST 使用**显式白名单**（`CORS_ALLOWED_ORIGINS`），生产 MUST NOT 用 `*`；`Access-Control-Allow-Credentials` 仅在白名单下开启 |
| CSRF | 采用 Bearer Token（非 Cookie）方案，故 CSRF 风险低；MUST NOT 把凭据放在 Cookie 里（若将来改为 Cookie，MUST 补 `SameSite` 与 CSRF Token） |
| SSRF | 网关 MUST NOT 发起由用户指定 URL 的请求。唯一的出站目标是配置里的 `AI_PLATFORM_BASE_URL`；`GET /documents/{id}/download` 的 302 目标来自 AI 返回的 presigned URL（可信来源） |
| 重定向 | 网关 MUST NOT 跟随 AI 返回的 3xx（防被利用做跳转），除非是显式的 download 接口 |
| 开放重定向 | 任何 `redirect_uri` 类参数 MUST 校验白名单（当前无此功能，作为约束保留） |

### 4.3 网络与限流边界

| 项 | 要求 |
| --- | --- |
| 真实客户端 IP | MUST 通过 `TRUSTED_PROXY_COUNT`（默认 1）从 `X-Forwarded-For` 的**右起第 N 个**取值；MUST NOT 直接取 XFF 首值（可被伪造绕过限流） |
| 内网暴露 | AI 端口 MUST NOT 暴露到公网；网关到 AI 的流量 MUST 在内网或 mTLS 隧道内 |
| 限流 | 见 [02-§5.3](./02-接口规范与鉴权.md)；限流器故障 MUST 降级为本地兜底限额，MUST NOT 全部放行 |
| 超时 | 所有出站调用 MUST 设超时（见 [04-§3.3](./04-AI服务编排与网关.md)）；MUST NOT 使用无超时的 client |

### 4.4 日志与数据脱敏（`REQ-NFR-005`）

**MUST 脱敏**（替换为 `***` 或截断）：

| 字段 | 处理 |
| --- | --- |
| `Authorization` 头、`access_token`、`refresh_token`、`password`、`password_hash`、`token_hash` | 完整替换为 `***` |
| `JWT_SECRET`、`INTERNAL_SERVICE_TOKEN`、DB/Redis 连接串中的密码 | 完整替换 |
| 用户提问与模型回答（`content`） | MUST NOT 出现在 INFO 及以上日志；DEBUG 下截断至 200 字符（仅本地开发开启） |
| 检索片段 `snippet` / 文档内容 | 同上 |
| 邮箱 | 日志中脱敏为 `a***@b.com` |
| `user_id` | 可保留（非 PII），但导出到第三方 trace 时 MUST 哈希（见 §5.1） |

**MUST NOT 记录**：完整请求体（除 DEBUG）、完整响应体、任何凭据明文。

**审计日志**（`audit_log`）的 `detail` 字段 MUST 先脱敏再入库。

### 4.5 需求

| ID | 需求 |
| --- | --- |
| `REQ-NFR-004` | 服务 MUST 满足 §4.1–§4.3 的全部安全要求；`prod` 环境下 CORS 白名单、HTTPS、`TRUSTED_PROXY_COUNT` 配置缺失时 MUST 拒绝启动 |
| `REQ-NFR-005` | 服务 MUST 按 §4.4 脱敏；MUST 有自动化测试断言日志中不含凭据模式（`AC-NFR-05`） |

## 5. 可观测性

### 5.1 分布式链路追踪（`REQ-NFR-006`，接缝 J3）

| 项 | 约定 |
| --- | --- |
| 标准 | OpenTelemetry Go SDK，OTLP 导出（Jaeger 为后端） |
| 服务名 | `OTEL_SERVICE_NAME`（默认 `go-services`） |
| 入站 | 读 `traceparent` 头；缺失则新建 root span。生成的 `trace_id` MUST 写回响应头 `X-Trace-Id` |
| **出站（关键）** | 调用 `ai-platform` 时 MUST 注入 `traceparent`（HTTP header 或 gRPC metadata），使两侧形成**同一条** trace |
| `trace_id` 复用 | 若 AI 返回的错误信封带 `trace_id`，网关 MUST **原样透传**给客户端（接缝 J2）；若与本侧 `trace_id` 不同，MUST 记 WARN + 指标 `gw_trace_mismatch_total` |
| 采样 | `parentbased_traceidratio`，默认 0.1；`DEBUG=true` 或业务标记 `X-Debug-Trace: 1` 时 1.0；**错误与降级链路 MUST 100% 采样** |

Span 清单：

| Span | 关键属性 |
| --- | --- |
| `http.server.request` | `http.method`, `http.route`, `http.status_code`, `user_id_hash` |
| `auth.verify` | `result`(`ok`/`expired`/`bad_signature`/`blacklisted`/`version_mismatch`), `elapsed_ms` |
| `quota.check` | `metric`, `used`, `limit`, `result`(`pass`/`exceeded`) |
| `db.conversation.seq_alloc` | `conversation_id`, `seq` |
| `db.message.insert` | `role`, `status`, `content_len` |
| `ai.chat` / `ai.chat_stream` | `use_rag`, `use_tools`, `model`, `first_token_ms`, `finish_reason`, `degraded` |
| `sse.forward` | `events_count`, `bytes_out`, `client_disconnected` |
| `circuit_breaker` | `target`, `state` |

`user_id` MUST 先做 HMAC-SHA256 截断（前 16 位 hex）再作为属性，MUST NOT 明文导出。

### 5.2 指标（`REQ-NFR-007`）

暴露端口：`METRICS_PORT`（默认 9100），独立于业务端口，MUST 限制来源 IP。
命名前缀统一 **`gw_`**（与 AI 侧的 `ai_` 前缀区分，Grafana 可并列展示）。

| 指标 | 类型 | 标签 | 说明 |
| --- | --- | --- | --- |
| `gw_requests_total` | Counter | `route`, `method`, `status` | 总请求数 |
| `gw_request_duration_seconds` | Histogram | `route` | 耗时（桶 0.005/0.01/0.03/0.1/0.3/1/3/10/30） |
| `gw_auth_failures_total` | Counter | `reason` | 鉴权失败原因分布 |
| `gw_login_attempts_total` | Counter | `result`(`ok`/`bad_credentials`/`rate_limited`/`locked`) | 登录 |
| `gw_token_refresh_total` | Counter | `result`(`ok`/`invalid`) | 刷新成功/失败计数 |
| `gw_quota_exceeded_total` | Counter | `metric` | 配额拦截次数 |
| `gw_rate_limited_total` | Counter | `scope` | 限流次数 |
| `gw_ai_requests_total` | Counter | `operation`, `result` | 对 AI 的调用 |
| `gw_ai_request_duration_seconds` | Histogram | `operation` | 对 AI 调用耗时 |
| `gw_ai_first_token_seconds` | Histogram | `use_rag` | 首 token（含 AI 侧） |
| `gw_ai_errors_total` | Counter | `code`, `upstream_status` | AI 错误码分布 |
| `gw_circuit_breaker_state` | Gauge | `target` | 0 关闭 / 1 半开 / 2 打开 |
| `gw_sse_connections` | Gauge | — | 当前活跃 SSE 连接数 |
| `gw_sse_client_disconnects_total` | Counter | `phase`(`before_first_token`/`mid_stream`/`after_done`) | 断连分布 |
| `gw_message_persist_failed_total` | Counter | `reason` | 落库失败（**必须有告警**） |
| `gw_session_mismatch_total` | Counter | — | AI 返回的 `conversation_id` 与网关不一致（接缝 J4 监控） |
| `gw_trace_mismatch_total` | Counter | — | trace_id 不一致（接缝 J3 监控） |
| `gw_orphan_rows_total` | Gauge | `table` | 每日一致性检查输出 |
| `gw_db_pool_*` / `gw_redis_pool_*` | Gauge | — | 连接池使用率 |
| `gw_build_info` | Gauge | `version`, `commit`, `go_version` | 版本信息（值恒 1） |

**禁止高基数标签**：`user_id`、`conversation_id`、`message_id`、`kb_id`、`doc_id`、`task_id`、`trace_id` MUST NOT 作为标签。`route` MUST 使用**路由模板**（`/conversations/{id}/messages`）而非真实路径。

### 5.3 日志（`REQ-NFR-008`）

| 项 | 约定 |
| --- | --- |
| 格式 | `log/slog` JSON（生产）/ text（本地，`LOG_FORMAT=text`） |
| 级别 | `LOG_LEVEL`（默认 `INFO`；本地 `DEBUG`） |
| 必备字段 | `ts`, `level`, `msg`, `service`, `version`, `trace_id`, `span_id`, `request_id` |
| 业务字段 | `user_id`, `route`, `method`, `status`, `elapsed_ms`, `upstream`(`ai-platform`), `code`(错误码), `degraded_reasons` |
| 级别选择 | `INFO`：请求完成摘要、状态变更。`WARN`：可恢复异常（降级、重试、缓存未命中关键项）。`ERROR`：请求失败、落库失败、不一致。`DEBUG`：仅本地，含截断内容 |
| 异常 | MUST 带结构化字段 `error_type`, `error_message`, `stack` |
| 关联 | 日志的 `trace_id` MUST 与 Jaeger trace、响应 `X-Trace-Id`、错误信封 `trace_id` 一致 |
| 输出 | 生产 MUST 输出到 stdout（由容器收集），MUST NOT 自己写文件与轮转 |

### 5.4 健康检查（`REQ-NFR-003` 之一）

| 端点 | 语义 | 检查项 | 状态码 |
| --- | --- | --- | --- |
| `GET /health/live` | 存活 | 仅进程在跑 | 恒 200 |
| `GET /health/ready` | 就绪 | MySQL 连通 + schema 版本 + Redis 连通 | 全通过 200；任一失败 503 |
| `GET /health` | 综合信息 | 上述 + AI 可达性 + 熔断状态（**仅信息，不影响状态码**） | 恒 200 |

`/health` 响应示例：

```json
{
  "status": "ok",
  "service": "go-services",
  "version": "0.1.0",
  "commit": "9f2c1ab",
  "checks": {
    "mysql": { "ok": true, "latency_ms": 3, "schema_version": "20260928_01" },
    "redis": { "ok": true, "latency_ms": 1 },
    "ai_platform": { "ok": false, "latency_ms": 3001, "error": "connection refused" },
    "circuit_breaker": { "target": "ai-platform", "state": "open" }
  }
}
```

> `ai_platform.ok = false` 时 `status` 为 `degraded`，但 **HTTP 状态码仍为 200** —— 这正是「AI 挂了不该摘除网关」的落地方式（见 §3）。

### 5.5 告警（`REQ-NFR-008` 之一）

| 规则 | 条件 | 级别 |
| --- | --- | --- |
| 消息落库失败 | `rate(gw_message_persist_failed_total[5m]) > 0` | **P1** |
| 会话 ID 不一致 | `increase(gw_session_mismatch_total[5m]) > 0` | P1（接缝破损） |
| 高错误率 | `gw_requests_total{status=~"5.."}` 占比 > 2% 持续 5 min | P1 |
| 熔断打开 | `gw_circuit_breaker_state{target="ai-platform"} == 2` 持续 2 min | P2 |
| SSE 首 token 劣化 | `histogram_quantile(0.95, gw_ai_first_token_seconds) > 3s` 持续 5 min | P2 |
| 鉴权失败激增 | `rate(gw_auth_failures_total[5m]) > 10/s` | P2（疑似攻击） |
| 连接池饱和 | `gw_db_pool_in_use / gw_db_pool_max > 0.9` 持续 5 min | P2 |
| 孤儿数据 | `gw_orphan_rows_total > 0` | P3 |

| ID | 关联需求 | 验收点 |
| --- | --- | --- |
| `AC-NFR-01` | `REQ-NFR-001` | 打 200 次 `GET /conversations`：网关自身耗时 P95 ≤ 80ms；对比直连 AI 的同类调用，网关增量 P95 ≤ 30ms |
| `AC-NFR-02` | `REQ-NFR-002` | 建立 500 条并发 SSE 连接并保持 60s：全部成功、无 5xx、RSS ≤ 512MB、`gw_sse_connections` = 500 |

| `AC-NFR-04` | `REQ-NFR-003` | `SIGTERM` 时有 3 个在途流式请求：20s 内全部正常结束（`done`）；25s 内进程退出；退出码 0 |
