# 06 · 非功能需求与可观测性

> 关联：需求 ID `REQ-NFR-*`；trace 接缝 J3 见 [01-§7](./01-总体需求与范围.md)；超时与降级见 [04-§3.3/§9](./04-AI服务编排与网关.md)；鉴权流程与错误码见 [02-§3/§4](./02-接口规范与鉴权.md)；Key/TTL 与表结构见 [05-§3](./05-数据模型.md)。本篇只写网关自身的硬约束。

## 1. 性能（`REQ-NFR-001`）

| 指标 | P50 | P95 | 说明 |
| --- | --- | --- | --- |
| **网关自身额外延迟** | 8 ms | **30 ms** | 鉴权 + 配额 + 转发，**不含** AI 侧耗时 |
| 鉴权中间件 / 配额校验 + 预扣 | 1 / 2 ms | 3 / 5 ms | JWT 验签 + `ver` 校验（至多一次 Redis 读）；配额走 Redis 管道 |
| 会话列表 `GET /conversations` | 30 ms | 80 ms | 单页 20 条，用户有 100 会话 |
| 消息分页 `GET .../messages` | 25 ms | 80 ms | 单页 20 条 |
| 消息落库（异步，不计入响应） | 5 ms | 20 ms | 含 `seq` 分配 |
| SSE 首帧 / 单帧转发 | 3 ms / 1 ms | 15 ms / 5 ms | 从收到 AI 帧到写出客户端 |
| 登录（含 Argon2id 校验） | 60 ms | 120 ms | 哈希成本固定，属 CPU 密集 |
| 上传转发吞吐 | — | — | 内网 ≥ 100 MB/s（流式 `io.Copy`） |

- 首 token 端到端 = AI 侧首 token + 网关增量（≤ 30 ms）；P50/P95 MUST 基于 ≥ 200 次采样。
- **MUST NOT** 在请求路径内做阻塞 I/O 之外的 CPU 密集操作（如批量哈希）—— 单帧省下的时间会被每个 token 乘一遍。

## 2. 容量与并发（`REQ-NFR-002/003`）

| 项 | 目标 |
| --- | --- |
| 单实例并发 | SSE 连接 ≥ 500；非 AI 接口 QPS ≥ 1000 |
| 单实例 AI 接口 | 受 AI 侧 `llm_max_concurrency` 约束；网关侧排队 ≤ 3 s |
| 单用户并发对话 | 5（配额 `concurrency`） |
| 规模上限 | 用户 10 000；会话/用户 1 000；消息/会话 20 000；消息/用户 200 000 |
| 请求体 / 响应体上限 | JSON 1 MB（`MAX_JSON_BODY_MB`，multipart 另受 `UPLOAD_MAX_MB`）/ 16 MB（`MAX_RESPONSE_MB`） |
| 内存 | 稳态 ≤ 256 MB（RSS）；500 SSE 连接下 ≤ 512 MB；每连接 ≤ 64 KB |

- 累积 MUST 有上限 `STREAM_ACCUMULATE_MAX_CHARS`（默认 64000）：超出后**继续透传客户端但停止累积**，落库截断并标 `status=partial`。网关为落库必须缓存全文，没有上限就等于给异常长回答留了一个内存放大器。
- `references` / `tool_calls` 的累积各上限 200 条，超出丢弃并记 WARN。
- 配额：`chat_requests` 在调用 AI **前**预扣（Redis `INCR` 原子），仅在 `AI_UNAVAILABLE`/`AI_TIMEOUT`/`INTERNAL_ERROR`/熔断拒绝时回滚；参数错误与内容过滤不回滚，否则重试型滥用可白嫖额度。维度与 Key 见 [02-§5.1–§5.2](./02-接口规范与鉴权.md)。

## 3. 可靠性与可用性（`REQ-NFR-004/005`）

| 项 | 目标 |
| --- | --- |
| 可用性 | 硬依赖（MySQL/Redis）健康时 99.9%（月度）；AI 挂着也算可用，仅 AI 接口降级 |
| 优雅退出 | `SIGTERM` 后停止接受新连接，在途流式给 `GRACEFUL_SHUTDOWN_SECONDS`（20s），进程 ≤ 30s 退出 |
| 幂等 | 见 [02-§7](./02-接口规范与鉴权.md)，MUST 覆盖所有「重试会产生副作用」的接口 |
| 数据不丢 | 已返回 `done` 的对话 MUST 最终落库（失败则告警并可人工补偿） |
| 时钟 | 所有实例 MUST 用 NTP 同步（JWT 容差仅 30s） |

退出顺序（MUST NOT 直接 `os.Exit`，会丢掉已累积未落库的回答）：停 accept → 等在途请求（上限 20s）→ 超时的流先发 `event: error(code=SERVICE_SHUTTING_DOWN)` 或 `done(finish_reason=canceled)` 并落库 partial → 关 AI/DB/Redis 连接池 → 退出。

就绪取舍：`/health/ready` **MUST NOT** 把 AI 可达性作为决定项 —— AI 抖一下就把网关摘掉，会把单点故障放大成全站不可用；AI 状态只进 `/health` 的信息字段。

熔断：连续 `CB_FAILURE_THRESHOLD`（10）次上游故障后打开 `CB_OPEN_SECONDS`（30s），期间不发起调用、直接返回 `AI_OVERLOADED` + `Retry-After`；冷却后半开放**一个**探针，成功才关闭。健康检查与客户端类错误（参数、内容过滤）不计入失败，否则一次参数错误潮就能熔断全网关。

## 4. 安全（`REQ-NFR-004` 之一）

> 鉴权流程、JWT 校验顺序与错误码只在 [02-§3/§4](./02-接口规范与鉴权.md) 写一遍；`refresh_token` 表与 `token_hash` 见 [05-§2.2](./05-数据模型.md)。本节只列硬约束。

### 4.1 认证与凭据
| 项 | 要求 |
| --- | --- |
| 密码存储 | Argon2id（`ARGON2_MEMORY_MB=64`、`ARGON2_ITERATIONS=3`、`ARGON2_PARALLELISM=4`、salt 16B、key 32B）；MUST NOT 用 MD5/SHA1/BCrypt-only |
| 时序侧信道 | MUST 用恒定时间比较；对**不存在的用户**也执行一次等价耗时哈希，否则可枚举邮箱 |
| 凭据形态 | 仅经 HTTPS 传输，MUST NOT 出现在 URL query；refresh 明文只出现一次，服务端只存 sha256 并轮换作废 |
| 登录防爆破 | 单 IP 10 次/分钟 + 单账号 20 次/小时；连续 5 次失败后触发验证码（P2） |
| 密钥 | `JWT_SECRET` / `INTERNAL_SERVICE_TOKEN` ≥ 32 字节随机，由 Secret 注入；MUST NOT 硬编码、入库、进日志 |

### 4.2 输入与输出安全
| 项 | 要求 |
| --- | --- |
| 注入 | 全部 SQL MUST 走参数化（GORM/`database/sql` 占位符），MUST NOT 拼接用户输入 |
| 请求体 / 内容类型 | MUST 用 `http.MaxBytesReader` 限 JSON 1 MB，超限 `413`（MUST NOT 先读进内存）；MUST 校验 `Content-Type`，`multipart` 限制文件数与字段数（防 multipart bomb） |
| 响应头 | `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；只返回 JSON，故 CSP 非必需 |
| CORS / CSRF | `CORS_ALLOWED_ORIGINS` 显式白名单，生产禁 `*`；Bearer Token 方案（非 Cookie），CSRF 风险低，凭据 MUST NOT 放 Cookie |
| SSRF / 重定向 | 唯一出站目标是 `AI_PLATFORM_BASE_URL`，MUST NOT 请求用户指定 URL；MUST NOT 跟随 AI 的 3xx（显式 download 除外）；`redirect_uri` 类参数 MUST 校验白名单（当前无此功能，约束保留） |

### 4.3 网络与限流边界
| 项 | 要求 |
| --- | --- |
| 真实客户端 IP | `TRUSTED_PROXY_COUNT`（默认 1）取 `X-Forwarded-For` 的**右起第 N 个**；取首值可被伪造绕过限流 |
| 内网暴露 | AI 端口 MUST NOT 暴露公网；网关到 AI 的流量 MUST 在内网或 mTLS 隧道内 |
| 限流 | 阈值见 [02-§5.3](./02-接口规范与鉴权.md)；限流器故障 MUST 降级为本地兜底限额，MUST NOT 全部放行 |
| 超时 | 所有出站调用 MUST 设超时（[04-§3.3](./04-AI服务编排与网关.md)），MUST NOT 使用无超时 client |

### 4.4 日志与数据脱敏（`REQ-NFR-005`）
| 字段 | 处理 |
| --- | --- |
| `Authorization`、`access_token`、`refresh_token`、`password`、`password_hash`、`token_hash`、`JWT_SECRET`、`INTERNAL_SERVICE_TOKEN`、DB/Redis 连接串密码 | 完整替换为 `***` |
| 提问与回答（`content`）、检索片段 `snippet`、文档内容 | MUST NOT 进 INFO 及以上；DEBUG 下截断至 200 字符（仅本地开发开启） |
| 邮箱 | 脱敏为 `a***@b.com` |
| `user_id` | 可保留（非 PII），但导出到第三方 trace 时 MUST 哈希（§5.1） |

- **MUST NOT 记录**：完整请求体/响应体（DEBUG 除外）、任何凭据明文；`audit_log.detail` MUST 先脱敏再入库。
- 留存：应用只写 stdout、MUST NOT 自写文件与轮转，采集与轮转交给运行环境；库内数据由 `RETENTION_DAYS=30`（软删物理清理）/ `USAGE_RETENTION_DAYS=90`（用量明细）/ `audit_log` ≥ 180 天约束（[05-§5](./05-数据模型.md)）。

### 4.5 需求
| ID | 需求 |
| --- | --- |
| `REQ-NFR-004` | 服务 MUST 满足 §4.1–§4.3 的全部安全要求；`prod` 下 CORS 白名单、HTTPS、`TRUSTED_PROXY_COUNT` 缺失时 MUST 拒绝启动 |
| `REQ-NFR-005` | 服务 MUST 按 §4.4 脱敏；MUST 有自动化测试断言日志不含凭据模式（`AC-NFR-05`） |

## 5. 可观测性

### 5.1 分布式链路追踪（`REQ-NFR-006`，接缝 J3）
| 项 | 约定 |
| --- | --- |
| 标准 / 服务名 | OpenTelemetry Go SDK，OTLP 导出（Jaeger 为后端）；`OTEL_SERVICE_NAME`（默认 `go-services`） |
| 入站 | 读 `traceparent`，缺失则新建 root span；生成的 `trace_id` MUST 写回响应头 `X-Trace-Id` |
| 出站（关键） | 调 `ai-platform` MUST 注入 `traceparent`（HTTP header 或 gRPC metadata），否则两侧各一条 trace，排障时链路正好断在接缝上 |
| `trace_id` 复用 | AI 错误信封带 `trace_id` 时 MUST 原样透传（接缝 J2）；与本侧不同则记 WARN + `gw_trace_mismatch_total` |
| 采样 | **尾部采样**：头部全量记录，按 trace 决策 —— 任一 span 为 `Error` 则整条导出；`gw.force_sample`（`DEBUG=true` 或 `X-Debug-Trace: 1`）导出；根 span 结束按 `OTEL_TRACES_SAMPLER_ARG`（0.1）抽签；TTL 15s 兜底，缓冲上限 4096 trace / 256 span |

| Span | 关键属性 |
| --- | --- |
| `http.server.request` | `http.method`, `http.route`, `http.status_code`, `user_id_hash` |
| `auth.verify` | `result`(`ok`/`expired`/`bad_signature`/`blacklisted`/`version_mismatch`), `elapsed_ms` |
| `quota.check` | `metric`, `used`, `limit`, `result`(`pass`/`exceeded`) |
| `db.conversation.seq_alloc` / `db.message.insert` | `conversation_id`+`seq` / `role`+`status`+`content_len` |
| `ai.chat` / `ai.chat_stream` | `use_rag`, `use_tools`, `model`, `first_token_ms`, `finish_reason`, `degraded` |
| `sse.forward` / `circuit_breaker` | `events_count`+`bytes_out`+`client_disconnected` / `target`+`state` |

`user_id` MUST 先做 HMAC-SHA256 截断（前 16 位 hex）再作为属性，MUST NOT 明文导出。

### 5.2 指标（`REQ-NFR-007`）

`METRICS_PORT`（默认 **9100**）独立于业务端口 8080，`METRICS_ALLOW_CIDRS`（默认 `127.0.0.1/32`）限制来源；命名前缀统一 **`gw_`**，与 AI 侧的 `ai_` 前缀在 Grafana 并列展示。

| 指标 | 类型 | 标签 | 说明 |
| --- | --- | --- | --- |
| `gw_requests_total` | Counter | `route`, `method`, `status` | 总请求数 |
| `gw_request_duration_seconds` | Histogram | `route` | 耗时（桶 0.005/0.01/0.03/0.1/0.3/1/3/10/30） |
| `gw_auth_failures_total` | Counter | `reason` | 鉴权失败原因分布 |
| `gw_login_attempts_total` | Counter | `result`(`ok`/`bad_credentials`/`rate_limited`/`locked`) | 登录 |
| `gw_token_refresh_total` | Counter | `result`(`ok`/`invalid`) | 刷新成功/失败 |
| `gw_quota_exceeded_total` | Counter | `metric` | 配额拦截次数 |
| `gw_rate_limited_total` | Counter | `scope` | 限流次数 |
| `gw_ai_requests_total` | Counter | `operation`, `result` | 对 AI 的调用 |
| `gw_ai_request_duration_seconds` | Histogram | `operation` | 对 AI 调用耗时 |
| `gw_ai_first_token_seconds` | Histogram | `use_rag` | 首 token（含 AI 侧） |
| `gw_ai_errors_total` | Counter | `code`, `upstream_status` | AI 错误码分布 |
| `gw_circuit_breaker_state` | Gauge | `target` | 0 关闭 / 1 半开 / 2 打开 |
| `gw_sse_connections` | Gauge | — | 当前活跃 SSE 连接数 |
| `gw_sse_client_disconnects_total` | Counter | `phase`(`before_first_token`/`mid_stream`/`after_done`) | 断连分布 |
| `gw_message_persist_failed_total` | Counter | `reason` | 落库失败（**必须有告警**） |
| `gw_session_mismatch_total` | Counter | — | AI 返回的 `conversation_id` 与网关不一致（接缝 J4） |
| `gw_trace_mismatch_total` | Counter | — | `trace_id` 不一致（接缝 J3） |
| `gw_orphan_rows_total` | Gauge | `table` | 每日一致性检查输出 |
| `gw_db_pool_*` / `gw_redis_pool_*` | Gauge | — | 连接池使用率 |
| `gw_build_info` | Gauge | `version`, `commit`, `go_version` | 版本信息（值恒 1） |

**禁止高基数标签**：`user_id`、`conversation_id`、`message_id`、`kb_id`、`doc_id`、`task_id`、`trace_id` MUST NOT 作为标签；`route` MUST 用路由模板（`/conversations/{id}/messages`）而非真实路径，否则 Prometheus 的 series 数会随用户数线性膨胀。

### 5.3 日志（`REQ-NFR-008`）
| 项 | 约定 |
| --- | --- |
| 格式 / 级别 | `log/slog` JSON（生产）或 text（`LOG_FORMAT=text`，本地）；`LOG_LEVEL` 默认 `INFO` |
| 必备 / 业务字段 | `ts`, `level`, `msg`, `service`, `version`, `trace_id`, `span_id`, `request_id`；业务侧 `user_id`, `route`, `method`, `status`, `elapsed_ms`, `upstream`(`ai-platform`), `code`, `degraded_reasons` |
| 级别选择 | `INFO` 请求摘要与状态变更；`WARN` 降级、重试、关键缓存未命中；`ERROR` 请求失败、落库失败、不一致；`DEBUG` 仅本地，含截断内容 |
| 异常 / 输出 | 异常 MUST 带 `error_type`、`error_message`、`stack`；生产只写 stdout 交容器收集，MUST NOT 自写文件与轮转 |

日志的 `trace_id` MUST 与 Jaeger trace、响应 `X-Trace-Id`、错误信封 `trace_id` 三处一致，否则排障时要凭时间戳猜。

### 5.4 健康检查（`REQ-NFR-003` 之一）
| 端点 | 语义 | 检查项 | 状态码 |
| --- | --- | --- | --- |
| `GET /health/live` | 存活 | 仅进程在跑 | 恒 200 |
| `GET /health/ready` | 就绪 | MySQL 连通 + schema 版本 + Redis 连通 | 全通过 200；任一失败 503 |
| `GET /health` | 综合信息 | 上述 + AI 可达性 + 熔断状态（**仅信息，不影响状态码**） | 恒 200 |

`/health` 响应（节选，字段不可缺；`circuit` 未启用时为 `{"state":"disabled"}`）：

```json
{"status":"degraded","service":"go-services","version":"0.1.0","commit":"9f2c1ab",
 "checks":{"mysql":{"ok":true,"latency_ms":3,"schema_version":"20260928_01"},"redis":{"ok":true,"latency_ms":1},
 "ai_platform":{"ok":false,"latency_ms":3001,"error":"connection refused"},"circuit_breaker":{"target":"ai-platform","state":"open"}}}
```

`ai_platform.ok=false` 时 `status` 为 `degraded` 但 HTTP 仍为 200 —— 这就是「AI 挂了不该摘除网关」的落地方式（见 §3）。

### 5.5 告警（`REQ-NFR-008` 之一）
| 规则 | 条件 | 级别 |
| --- | --- | --- |
| 消息落库失败 | `rate(gw_message_persist_failed_total[5m]) > 0` | **P1** |
| 会话 ID 不一致 | `increase(gw_session_mismatch_total[5m]) > 0` | P1（接缝破损） |
| 高错误率 | `gw_requests_total{status=~"5.."}` 占比 > 2% 持续 5 min | P1 |
| 熔断打开 | `gw_circuit_breaker_state{target="ai-platform"} == 2` 持续 2 min | P2 |
| SSE 首 token 劣化 | `histogram_quantile(0.95, gw_ai_first_token_seconds) > 3s` 持续 5 min | P2 |
| 鉴权失败激增 | `rate(gw_auth_failures_total[5m]) > 10/s` | P2（疑似攻击） |
| 连接池饱和 | `gw_db_pool_in_use / gw_db_pool_max > 0.9` 持续 5 min | P2 |
| 孤儿数据 | `gw_orphan_rows_total > 0` | P3 |

## 6. 配置与部署（`REQ-NFR-009/010`）

| ID | 需求 |
| --- | --- |
| `REQ-NFR-009` | 全部配置 MUST 通过环境变量注入（12-Factor），MUST 提供 `.env.example`；`prod` 下 `JWT_SECRET`、`MYSQL_DSN`、`REDIS_URL`、`AI_PLATFORM_BASE_URL` 缺失或为默认值即拒绝启动 |
