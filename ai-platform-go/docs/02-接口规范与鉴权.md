## 2. 统一响应结构
### 2.1 成功
| 场景 | 形态 |
| --- | --- |
| 单对象 | 直接返回业务对象，不额外包 `data` |
| 列表 | `{"items": [], "next_cursor": null, "has_more": false}` |
| 创建 / 删除 | `201` + 资源对象（`Location` 头 SHOULD 带新资源 URL）/ `204` 无响应体 |
| 异步受理 | `202` + `{task_id, ...}` |

### 2.2 失败（与 AI 侧同构的错误信封）
```json
{"error": {"code": "QUOTA_EXCEEDED", "message": "今日对话次数已用完，请明天再试或升级配额",
  "details": {"metric": "chat_requests", "limit": 100, "used": 100, "reset_at": "2026-09-29T00:00:00.000Z"},
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736", "retryable": false}}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `error.code` | 是 | 见 §4，机器可读 |
| `error.message` | 是 | 可被客户端直接展示；不泄漏内部细节 |
| `error.details` | 否 | 结构化补充（`fields[]`、额度、冲突资源 ID） |
| `error.trace_id` | 是 | 与日志、Jaeger 一致；**透传 AI 侧时 MUST 沿用 AI 的 `trace_id`** |
| `error.retryable` / `error.retry_after` | 是 / 否 | 可否安全重试；`retry_after` 为秒数，仅 `retryable=true` |

## 3. JWT 签发契约（接缝 J1 —— 最高优先级）
### 3.1 令牌类型
| 令牌 | 形态 | TTL | 存储 | 用途 |
| --- | --- | --- | --- | --- |
| **Access Token** | JWT（自包含） | `ACCESS_TOKEN_TTL_MINUTES`（默认 30min） | 客户端内存 | 每次请求鉴权；**同时被 `ai-platform` 校验** |
| **Refresh Token** | 不透明随机串（32 字节 base64url） | `REFRESH_TOKEN_TTL_DAYS`（默认 30 天） | **HttpOnly Cookie**（`ai_refresh`，Path=`/api/v1/auth`，SameSite=Lax）；服务端只存 SHA-256 哈希 | 仅用于换新 Access Token |

> Refresh Token **不是 JWT**：它只是一张「允许换新 access」的凭证，存库只是为了能撤销（改密码、踢下线）。
> **B-08**：refresh 只通过 `Set-Cookie: ai_refresh=...; HttpOnly; SameSite=Lax; Path=/api/v1/auth` 下发，
> 不进 JSON、不进 localStorage。本地 HTTP 不设 `Secure`；HTTPS 直连或反代 `X-Forwarded-Proto=https` 时自动设置。
> 跨站请求由 SameSite 与 `Sec-Fetch-Site` 双重拦截。
> CLI/脚本仍可用 body `refresh_token` 刷新，此时响应会带新的 `refresh_token`；浏览器 Cookie 模式不带。
> **本设计有意不做**（成熟产品的加固项，对本项目复杂度超出收益）：refresh 轮换链（`family`）、access 黑名单（`jti` 表）、登录设备列表、非对称签名（RS256/JWKS）。代价明确：登出后 access 在剩余 TTL（≤ 30min）内仍可用，靠客户端丢弃本地 token；即时失效靠 `ver`（改密码 / `logout_all` 时递增）。

### 3.2 Access Token 结构（MUST 严格遵守）
- Header：`{"alg": "HS256", "typ": "JWT", "kid": "k1"}`。

| Claim | 类型 | 必填 | 值 / 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `iss` | string | 是 | `ai-assistant` | `ai-platform` 校验此值 |
| `aud` | string | 是 | `ai-platform` | **`ai-platform` 校验此值，写错即全部 401** |
| `sub` | string | 是 | 用户 ID，形如 `u_01J8...` | **`ai-platform` 用它作为 `user_id`，是数据隔离的唯一依据** |
| `exp` | number | 是 | `iat + ACCESS_TOKEN_TTL_MINUTES` | 过期时间（秒） |
| `iat` | number | 是 | 签发时间 | — |
| `nbf` | number | 是 | 等于 `iat` | 不接受早于此刻的令牌 |
| `token_type` | string | 是 | 固定 `access` | 防 Refresh Token 被当 Access 用 |
| `ver` | number | 是 | 令牌版本（对应用户的 `token_version`） | 改密码/踢下线时递增，旧令牌全部失效 |

**签名与密钥**

| 项 | 约定 |
| --- | --- |
| 算法 | **HS256**（与 `ai-platform` 共享 `JWT_SECRET`）。不做非对称签名与 JWKS：只有两个服务、密钥同源注入，引入 JWKS 只会多一个密钥分发故障面 |
| 密钥 | 环境变量 / Secret 注入；MUST NOT 硬编码或入库；长度 ≥ 32 字节随机；`kid` 固定 `k1`（保留字段，换密钥不改协议，当前不做轮换） |
| `alg` 校验 | 校验方 MUST **固定期望算法**，禁止接受 `none` 或按 token 头部选算法（防 alg confusion）。这是唯一真正必要的 JWT 加固项 |

**⚠️ 反向要求**：`ai-platform` MUST 与本表一致（其 SRS 已声明同样的 `iss`/`aud`/`sub`）；任一项不一致都会导致**全链路 401**，故 MUST 有互操作测试（见 [07-§3 `AC-TEST-01`](./07-验收标准与测试策略.md)）。

### 3.3 令牌校验顺序（网关中间件）
校验顺序（任一步失败即 `401`）：① `Authorization` 头存在且为 `Bearer ` 前缀 → ② 固定 HS256 验签 → ③ `iss == "ai-assistant"` → ④ `aud == "ai-platform"` → ⑤ `exp` / `nbf`（容差 ≤ 30s，`JWT_CLOCK_SKEW_SECONDS`） → ⑥ `token_type == "access"` → ⑦ `ver == 当前 token_version`（Redis `gw:user:ver:{user_id}`，TTL 10min，未命中查 MySQL） → ⑧ 注入 `user_id = sub` 到上下文。

失败响应 MUST NOT 泄漏具体原因（防探测），但 `error.code` MAY 区分 `TOKEN_EXPIRED` 与 `UNAUTHENTICATED` 以便客户端静默刷新。② 为本地计算、⑦ 至多一次 Redis 读，总耗时 ≤ 3ms（P95）。

**身份透传**：鉴权通过后网关 MUST 把客户端原始 `Authorization` 头原样转给 AI（由 AI 再校验一遍），MUST NOT 自造 `user_id` 头让 AI 信任（防伪造）；细节见 [04-§3.2](./04-AI服务编排与网关.md)。

### 3.4 需求
| ID | 需求 |
| --- | --- |
| `REQ-AUTH-002` | 服务 MUST 按 §3.2 签发符合 `ai-platform` 校验要求的 Access Token，并提供互操作测试证明两侧一致。**本项是接缝 J1，不可简化** |
| `REQ-AUTH-003` | 刷新时 MUST 签发新的 Refresh Token 并作废旧的（单次有效）；已作废令牌再被使用 MUST 返回 `401 INVALID_REFRESH_TOKEN` |
| `REQ-AUTH-004` | 登出 MUST 作废该用户的 Refresh Token（`logout_all=true` 时作废其**全部** Refresh Token 并递增 `token_version`）。Access Token 不做服务端黑名单，依赖客户端丢弃 + `ver` 校验 |

## 4. 错误码
> 分两类：**网关自有**（AI 不产生）与**复用 AI 侧**（网关仅透传，不重写——接缝 J2）。

### 4.1 网关自有错误码
| code | HTTP | retryable | message（zh-CN） | 触发条件 |
| --- | --- | --- | --- | --- |
| `INVALID_ARGUMENT` | 400 | 否 | 请求参数不合法 | 校验失败，`details.fields` 列出字段 |
| `UNAUTHENTICATED` | 401 | 否 | 身份未认证 | 缺 token / 签名错 / `ver` 不匹配 |
| `TOKEN_EXPIRED` | 401 | 否 | 登录已过期 | `exp` 过期；客户端**据此触发刷新** |
| `INVALID_CREDENTIALS` | 401 | 否 | 账号或密码错误 | 登录失败（与"用户不存在"同一码，防枚举） |
| `INVALID_REFRESH_TOKEN` | 401 | 否 | 刷新令牌无效 | 不存在 / 已作废 / 已过期 |
| `PERMISSION_DENIED` | 403 | 否 | 无权访问该资源 | 越权（**仅用于非资源存在性场景**；资源不存在一律 404） |
| `USER_DISABLED` | 403 | 否 | 账号已被禁用 | 用户状态非 `active` |
| `RESOURCE_NOT_FOUND` | 404 | 否 | 资源不存在 | 通用 404 |
| `CONVERSATION_NOT_FOUND` | 404 | 否 | 会话不存在 | `cv_id` 未知/越权/已删 |
| `MESSAGE_NOT_FOUND` | 404 | 否 | 消息不存在 | `msg_id` 未知/越权 |
| `CONFLICT` | 409 | 否 | 资源冲突 | 通用冲突 |
| `EMAIL_ALREADY_EXISTS` | 409 | 否 | 该邮箱已被注册 | 注册 |
| `CONVERSATION_ARCHIVED` | 409 | 否 | 会话已归档，不可发送消息 | 向归档会话发消息 |
| `PAYLOAD_TOO_LARGE` | 413 | 否 | 请求体过大 | 超过 `MAX_JSON_BODY_MB`（默认 1） |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | 否 | 不支持的内容类型 | Content-Type 不匹配 |
| `QUOTA_EXCEEDED` | 429 | 否 | 配额已用完 | 见 §5.2 |
| `RATE_LIMITED` | 429 | 是 | 请求过于频繁 | 见 §5.3，带 `retry_after` |
| `INTERNAL_ERROR` | 500 | 是 | 服务内部错误 | 未捕获异常 |
| `AI_UNAVAILABLE` | 503 | 是 | AI 服务暂时不可用，请稍后重试 | AI 侧不可达/熔断打开 |
| `AI_OVERLOADED` | 503 | 是 | AI 服务繁忙 | AI 侧返回 `OVERLOADED` |
| `DEPENDENCY_UNAVAILABLE` | 503 | 是 | 依赖服务不可用 | MySQL/Redis 不可用 |
| `AI_TIMEOUT` | 504 | 是 | AI 服务响应超时 | AI 侧调用超时 |

### 4.2 复用 `ai-platform` 的错误码（网关 MUST 原样透传）
> 全量码表与 message 以 `ai-platform/docs/02` 为准，下表只列网关需识别的码与状态码。

| code | HTTP | 说明 |
| --- | --- | --- |
| `UPSTREAM_LLM_ERROR` / `UPSTREAM_LLM_AUTH_ERROR` / `TOOL_EXECUTION_FAILED` / `UPSTREAM_MCP_ERROR` / `SUMMARY_GENERATION_FAILED` | 502 | 模型 / 工具 / MCP / 摘要上游失败 |
| `UPSTREAM_TIMEOUT` / `TOOL_TIMEOUT` | 504 | 上游超时 |
| `CONTEXT_TOO_LONG` / `QUERY_EMPTY` / `CONTENT_FILTERED`（400）、`TOOL_FORBIDDEN`（403） | 400 / 403 | AI 侧拒绝请求 |
| `KB_NOT_FOUND` / `DOCUMENT_NOT_FOUND` / `TASK_NOT_FOUND` / `MEMORY_NOT_FOUND` / `TOOL_NOT_FOUND` / `MCP_SERVER_NOT_FOUND` / `SUMMARY_UNAVAILABLE` | 404 | AI 侧资源不存在 |
| `KB_NAME_CONFLICT` / `DOCUMENT_DUPLICATE` / `KB_NOT_EMPTY` / `TASK_NOT_CANCELABLE` / `TASK_NOT_RETRYABLE` | 409 | AI 侧状态冲突 |
| `FILE_TOO_LARGE`（413）/ `UNSUPPORTED_FILE_TYPE`（415）/ `UNPROCESSABLE_DOCUMENT`（422） | 413 / 415 / 422 | 上传与解析校验 |
| `MCP_SERVER_UNAVAILABLE` / `RETRIEVAL_FAILED` / `OVERLOADED` | 503 | AI 侧不可用 / 过载 |

**透传规则（MUST）**：

1. 保留 `error.code`、`error.message`、`error.details`、`error.retryable` 与 HTTP 状态码原值。
2. 保留 `error.trace_id`（**不是**替换成网关自己的 request id）——否则排障时链路断裂。
3. 网关 MAY 在 `details` 中**追加** `gateway` 对象（如 `{"gateway":{"upstream":"ai-platform"}}`），但 MUST NOT 修改或删除原有键。
4. AI 返回非约定格式（如 502 网关错误页）时 MUST 归一化为 `AI_UNAVAILABLE` / `AI_TIMEOUT`，原始状态码放 `details.upstream_status`。
5. `FILE_TOO_LARGE` / `UNSUPPORTED_FILE_TYPE` 网关侧 SHOULD 按同规则提前拦截，避免无谓转发。

## 5. 配额与限流
### 5.1 配额维度
| 指标 (`metric`) | 单位 | 默认（免费档） | 说明 |
| --- | --- | --- | --- |
| `chat_requests` | 次 | 100 / 天 | 对话请求数（含流式） |
| `llm_tokens` | token | 200000 / 天 | 按 AI 上报 `usage.total_tokens` 累计 |
| `kb_count` | 个 | 3 | 知识库数量（上限，非按天） |
| `documents_count` | 个 | 50 | 文档数量（上限） |
| `storage_bytes` | 字节 | 536870912（512MB） | 已上传原始文件总量 |
| `concurrency` | 路 | 5 | **并发**对话数（瞬时，非累计） |

- 周期：`chat_requests` / `llm_tokens` 为**自然日**（`QUOTA_TIMEZONE`，默认 `Asia/Shanghai`），`reset_at` 为次日 00:00；`kb_count` / `documents_count` / `storage_bytes` 为**存量上限**，删除资源后释放。配额值由 `plan` 决定（`QUOTA_PLAN_MAP`），MUST NOT 硬编码。

### 5.2 扣减语义（接缝 J7）
| 项 | 动作 |
| --- | --- |
| ① 读配额 | Redis `gw:quota:{user_id}:{metric}:{period}`，未命中回源 MySQL 并回填（不回填则重启后首次校验看到 0） |
| ② 校验 | 不足 → `429 QUOTA_EXCEEDED`（details 带 `limit`/`used`/`reset_at`），**不调用 AI** |
| ③ 预扣 | `chat_requests += 1`（Redis 原子 `INCR`；日指标键 TTL 到周期结束 + 1h，存量指标不设 TTL）。MUST 在调用 AI **之前**完成，防并发绕过 |
| ④ 调用 AI | 成功且拿到 `usage` → ⑤；失败 → ⑥ |
| ⑤ 累加 | 按 `usage.total_tokens` 累加 `llm_tokens`，并写 `usage_record` 明细 |
| ⑥ 回滚 | `chat_requests -= 1`：仅 `AI_UNAVAILABLE` / `AI_OVERLOADED` / `AI_TIMEOUT` / `DEPENDENCY_UNAVAILABLE` / `INTERNAL_ERROR` / 停机拒绝（`SERVICE_SHUTTING_DOWN`）；参数错误与内容过滤**不**回滚（否则重试可刷配额） |
| 异步对账 | 每 5 分钟用脏集合 `gw:quota:dirty` 把 Redis 快照写回 MySQL `quota_usage`（`QuotaService.Reconcile` 已实现，当前未接入后台循环） |
| 权威性 | 每日 0 点以 MySQL 为准重建 Redis 计数（Redis 是加速器，不是唯一真源） |
| 并发配额 | `concurrency` 用 `gw:cc:{user_id}` 计数器 + 请求结束/断开时 `DECR`（MUST 在 defer 中保证释放） |
| 只读不写 | `ai-platform` **MUST NOT** 扣减配额，只上报 `usage`（否则双重扣减） |

### 5.3 限流（`REQ-AUTH-008`）
| 维度 | 默认阈值 | 超限 |
| --- | --- | --- |
| 单 IP 登录尝试 | 10 次 / 分钟（`LOGIN_RATE_PER_MINUTE`） | `429 RATE_LIMITED` |
| 单账号登录尝试 | 20 次 / 小时（`LOGIN_ACCOUNT_RATE_PER_HOUR`，按邮箱 SHA-256 前 16 位计数；单 IP 挡不住分布式撞库） | `429` |
| 单用户会话创建 | 30 次 / 分钟（`CONV_RATE_PER_MINUTE`） | `429` |
| 单用户消息发送 | 20 次 / 分钟（`MSG_RATE_PER_MINUTE`） | `429` |
| 单用户文档上传 | 10 次 / 分钟（`UPLOAD_RATE_PER_MINUTE`） | `429` |
| 单用户并发对话 | 5（= 配额 `concurrency`） | 排队 3s，仍满则 `429 RATE_LIMITED` |
| 全局入站 QPS | `GLOBAL_QPS_LIMIT`（默认 500） | `503 AI_OVERLOADED` |

实现：Redis 固定窗口计数（`gw:rate:{scope}:{id}:{bucket}`，`bucket` 是窗口起点 unix 秒，窗口切换由 Key 名完成）；响应 MUST 带 `Retry-After`（秒）；拒绝记 `gw_rate_limited_total{scope}`。Redis 不可用时降级为进程内计数（有限容量），MUST NOT 全部放行。

**B-07 剩余额度头**：所有挂了限流中间件的响应同时带
`X-RateLimit-Scope`、`X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset`
（Reset 为窗口结束的 unix 秒）。浏览器需通过 CORS `Access-Control-Expose-Headers` 读取。

### 5.4 需求
| ID | 需求 |
| --- | --- |
| `REQ-AUTH-006` | 服务 MUST 在调用 AI 之前完成配额校验与预扣，配额不足时 MUST NOT 产生对 `ai-platform` 的调用 |
| `REQ-AUTH-007` | 服务 MUST 提供用量查询接口，返回各 metric 的 `limit`/`used`/`remaining`/`reset_at` 及近 N 日明细 |
| `REQ-AUTH-008` | 服务 MUST 实现 §5.3 的多维限流，且 MUST NOT 因限流器故障而放行全部请求（Redis 不可用时按本地兜底限额降级，并记告警） |

## 6. 接口清单
> 全量 58 处路由注册：认证与用户/配额在本节；会话见 [03-§2](./03-用户与会话服务.md)；AI 透传见 [04-§7](./04-AI服务编排与网关.md)。

### 6.1 认证
| 方法 | 路径 | 说明（一句话契约） | 成功码 |
| --- | --- | --- | --- |
| `POST` | `/auth/register` | 注册（`email` + `password` + `nickname?`），Argon2id 哈希 + 弱口令拒绝 | 201 |
| `POST` | `/auth/login` | 登录，返回 access，并通过 HttpOnly Cookie 下发 refresh；凭证错误统一 `INVALID_CREDENTIALS` | 200 |
| `POST` | `/auth/refresh` | 从 Cookie 读 refresh 换新 access，轮换 Cookie（旧 refresh 立即作废） | 200 |
| `POST` | `/auth/logout` | 登出（Cookie 或 body `refresh_token`；`logout_all` 可选），清 Cookie | 204 |
| `POST` | `/auth/password` | 修改密码（需旧密码），成功后踢下线所有设备 | 204 |

`POST /auth/login` 请求字段：`email`（string，必填，合法邮箱 ≤ 254，统一小写化后比对）、`password`（string，必填，8..128 字符）、`device_name`（string，可选，≤ 64 字符，超长截断）。

响应（`user` 结构同 `GET /me`；refresh 只在 `Set-Cookie` 里）：

```http
Set-Cookie: ai_refresh=...; Path=/api/v1/auth; Max-Age=2592000; HttpOnly; SameSite=Lax
```

```json
{"access_token": "eyJhbGciOiJIUzI1NiIs...",
 "token_type": "Bearer", "expires_in": 1800,
 "user": {"id": "u_01J8ZQ3K7N9P2V6R4T8W1Y5B3C", "email": "a@b.com", "nickname": "小助手", "plan": "free", "status": "active", "created_at": "2026-09-28T10:00:00.123Z"}}
```

### 6.2 用户与配额
| 方法 | 路径 | 说明（一句话契约） | 成功码 |
| --- | --- | --- | --- |
| `GET` | `/me` | 当前用户（含 `plan`；MUST NOT 返回密码哈希、`token_version`、内部状态字段） | 200 |
| `PATCH` | `/me` | 修改 `nickname`（≤ 64 字符） | 200 |
| `GET` | `/me/quota` | 配额概览（各 metric 的 `limit`/`used`/`remaining`/`unit`/`reset_at`） | 200 |
| `GET` | `/me/usage` | 用量明细（`from`/`to`/`metric` 过滤；缺省近 24h，`limit` ≤ 100） | 200 |

### 6.3 需求
| ID | 需求 |
| --- | --- |
| `REQ-AUTH-001` | 注册 MUST 用 Argon2id 哈希密码（`memory=64MB`、`iterations=3`、`parallelism=4`，参数可配置），并 MUST 校验密码强度下限（长度 ≥ 8、非常见弱口令） |
| `REQ-AUTH-005` | `GET /me` MUST 只返回当前 JWT 对应的用户，且 MUST NOT 返回密码哈希、`token_version`、内部状态字段 |
| `REQ-AUTH-009` | 生产环境 MUST 仅接受 HTTPS；HTTP 请求 MUST 301 到 HTTPS（或由前置 LB 终止并强制） |
| `REQ-AUTH-010` | 所有列表接口 MUST 使用游标分页，`limit` 超上限返回 `INVALID_ARGUMENT` 而非静默截断 |

## 7. 幂等
| 接口 | 幂等机制 |
| --- | --- |
| `POST /auth/register` | 自然幂等：同邮箱返回 `409 EMAIL_ALREADY_EXISTS` |
| `POST /auth/refresh` | **非幂等**：每次返回新 refresh（旧的立即作废）。客户端 MUST 串行化刷新；并发刷新误用旧令牌返回 401，重新登录即可 |
| `POST /conversations` | 支持 `Idempotency-Key`，24h 内同键返回同一会话 |
| `POST /conversations/{id}/messages` | 支持 `Idempotency-Key`，防「重试导致重复提问」（**仅非流式**；`/messages/stream` 不挂幂等） |
| 上传文档 | 透传 `Idempotency-Key` 给 AI 侧（AI 据此返回同一 `task_id`） |
| `DELETE *` | 幂等；删除不存在资源返回 `404`（不返回 204，避免掩盖越权） |
| 其它 `POST`（如 `/logout`） | 幂等：重复登出返回 204 |

`Idempotency-Key` 建议 UUID，≤ 128 字符、字符集 `[A-Za-z0-9_.:-]`；唯一键 `(user_id, method, 路由模板, key)`，命中则回放首次响应（含状态码与响应体，并带 `Idempotency-Replayed: true`）；同键不同请求体（`request_hash` 不同）返回 `409 CONFLICT`；存储不可用只告警、不阻断业务。存储表见 [05-§2.7](./05-数据模型.md)。

## 8. 验收标准
| ID | 关联需求 | 验收点 |
| --- | --- | --- |
| `AC-AUTH-01` | `REQ-AUTH-001` | 注册后 MySQL 中 `password_hash` 以 `$argon2id$` 开头；用弱口令（`12345678`）注册返回 400 |
| `AC-AUTH-02` | `REQ-AUTH-002` | 解码登录返回的 access_token：`iss=ai-assistant`、`aud=ai-platform`、`sub` 为 `u_*`、含 `ver`/`token_type=access` |
| `AC-AUTH-03` | `REQ-AUTH-002` | 把 `aud` 改成 `ai-assistant` 后重新签发 → `ai-platform` 返回 `401 UNAUTHENTICATED`（证明该字段是硬约束，且互操作测试能抓到） |
| `AC-AUTH-04` | `REQ-AUTH-003` | 用同一 refresh 连续刷新两次 → 第二次返回 `401 INVALID_REFRESH_TOKEN`（旧令牌已作废） |
| `AC-AUTH-05` | `REQ-AUTH-004` | 登出后用原 refresh 刷新 → 401；`logout_all=true` 后旧 access 因 `ver` 不匹配 → 401 |
| `AC-AUTH-06` | `REQ-AUTH-006` | 把 `chat_requests` 限额改为 1，发第 2 次对话 → `429 QUOTA_EXCEEDED`，且 `ai-platform` 侧**未收到**任何调用（查其访问日志） |
| `AC-AUTH-07` | `REQ-AUTH-006` | 让 AI 返回 `503`，观察配额：`chat_requests` 回滚为原值；再让 AI 返回 `400 QUERY_EMPTY`，观察配额**未**回滚 |
| `AC-AUTH-08` | `REQ-AUTH-008` | 1 分钟内第 11 次登录尝试返回 `429`，且响应带 `Retry-After`；用另一 IP 请求正常 |
| `AC-AUTH-09` | `REQ-AUTH-005` | `GET /me` 响应 JSON 中不含 `password` / `token_version` / `hash` 任一子串 |
| `AC-AUTH-10` | `REQ-AUTH-010` | `limit=101` 返回 400；造 55 条会话翻 3 页，三页 ID 并集无重复无遗漏 |
