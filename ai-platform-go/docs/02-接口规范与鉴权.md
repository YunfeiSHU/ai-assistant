# 02 · 接口规范与鉴权

> 关联：需求 ID `REQ-AUTH-*`；接缝 J1/J2/J7 见 [01-§7](./01-总体需求与范围.md)；对 `ai-platform` 的调用见 [04](./04-AI服务编排与网关.md)。
>
> **本篇的「通用约定 / 错误信封 / 错误码」MUST 与 `ai-platform/docs/02-接口规范与错误码.md` 逐字一致** —— 客户端与网关之间、网关与 AI 之间共用同一套语义，任何差异都是接缝缺陷。

| 项 | 约定 | 需求 ID |

| 字段命名 | `snake_case`，不接受 camelCase | — |
| 未知字段 | 请求体未知字段 MUST 被忽略 | — |
| 时间格式 | RFC 3339 UTC 毫秒，`Z` 结尾 | — |

### 1.1 鉴权豁免路径（白名单）

| 路径 | 说明 |
| --- | --- |
| `/health/live`、`/health/ready` | 探活 |
| `/openapi.json`、`/docs`、`/redoc` | 文档 |
| `/metrics`（若同端口） | 指标，MUST 限制来源 IP |
| `POST /auth/register`、`POST /auth/login`、`POST /auth/refresh` | 认证入口 |

**其余全部路径 MUST 要求 `Authorization: Bearer <access_token>`**。

## 2. 统一响应结构

### 2.1 成功

- 单对象：直接返回业务对象，不额外包 `data`。
- 列表：`{"items": [], "next_cursor": null, "has_more": false}`。
- 创建：`201` + 资源对象；`Location` 头 SHOULD 带上新资源 URL。
- 删除：`204` 无响应体。
- 已受理异步：`202` + `{task_id, ...}`。

### 2.2 失败（与 AI 侧同构的错误信封）

```json
{
  "error": {
    "code": "QUOTA_EXCEEDED",
    "message": "今日对话次数已用完，请明天再试或升级配额",
    "details": { "metric": "chat_requests", "limit": 100, "used": 100, "reset_at": "2026-09-29T00:00:00.000Z" },
    "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
    "retryable": false
  }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `error.code` | 是 | 见 §4，机器可读 |
| `error.message` | 是 | 可被客户端直接展示；不泄漏内部细节 |
| `error.details` | 否 | 结构化补充（字段名、额度、冲突资源 ID） |
| `error.trace_id` | 是 | 与日志、Jaeger 一致；**透传 AI 侧时 MUST 沿用 AI 的 `trace_id`** |
| `error.retryable` | 是 | 客户端可否安全重试 |
| `error.retry_after` | 否 | 秒数，仅 `retryable=true` |

## 3. JWT 签发契约（接缝 J1 —— 最高优先级）

### 3.1 令牌类型

| 令牌 | 形态 | TTL | 存储 | 用途 |
| --- | --- | --- | --- | --- |
| **Access Token** | JWT（自包含） | `ACCESS_TOKEN_TTL`（默认 30min） | 客户端内存 | 每次请求鉴权；**同时被 `ai-platform` 校验** |
| **Refresh Token** | 不透明随机串（32 字节 base64url） | `REFRESH_TOKEN_TTL`（默认 30 天） | 客户端安全存储；**服务端只存 SHA-256 哈希** | 仅用于换新 Access Token |

> Refresh Token **不是 JWT**：它只是一张「允许换新 access」的凭证，存库只是为了能撤销（改密码、踢下线）。
>
> **本设计有意不做的事**（属于成熟产品的加固项，对本项目复杂度超出收益）：refresh 轮换链（`family`）、access 黑名单（`jti` 表）、登录设备列表、非对称签名（RS256/JWKS）。**代价是明确的**：登出后 access token 在剩余 TTL（≤ 30min）内仍可用，靠客户端丢弃本地 token 解决；真正的即时失效靠 `ver`（改密码 / `logout_all` 时递增），已覆盖主要场景。

### 3.2 Access Token 结构（MUST 严格遵守）

**Header**

```json
{ "alg": "HS256", "typ": "JWT", "kid": "k1" }
```

**Payload**

| Claim | 类型 | 必填 | 值 / 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `iss` | string | 是 | `ai-assistant` | `ai-platform` 校验此值 |
| `aud` | string | 是 | `ai-platform` | **`ai-platform` 校验此值，写错即全部 401** |
| `sub` | string | 是 | 用户 ID，形如 `u_01J8...` | **`ai-platform` 用它作为 `user_id`，是数据隔离的唯一依据** |
| `exp` | number | 是 | `iat + ACCESS_TOKEN_TTL` | 过期时间（秒） |
| `iat` | number | 是 | 签发时间 | — |
| `nbf` | number | 是 | 等于 `iat` | 不接受早于此刻的令牌 |
| `token_type` | string | 是 | 固定 `access` | 防 Refresh Token 被当 Access 用 |
| `ver` | number | 是 | 令牌版本（对应用户的 `token_version`） | 改密码/踢下线时递增，旧令牌全失效 |

**签名算法与密钥**

| 项 | 约定 |
| --- | --- |
| 算法 | **HS256**（与 `ai-platform` 共享 `JWT_SECRET`）。不做非对称签名与 JWKS：本系统只有两个服务、密钥同源注入，引入 JWKS 只会多一个密钥分发故障面 |
| 密钥来源 | 环境变量 / Secret 注入；MUST NOT 硬编码或入库 |
| 密钥长度 | ≥ 32 字节随机值 |
| `kid` | 固定 `k1`（保留字段，以便将来换密钥不改协议；当前不做轮换流程） |
| `alg` 校验 | 校验方 MUST **固定期望算法**，禁止接受 `none` 或按 token 头部选择算法（防 alg confusion）。这条 MUST 保留，是唯一真正必要的 JWT 加固项 |

**⚠️ 反向要求**：`ai-platform` 的实现 MUST 与本表一致（其 SRS 已声明 `iss=ai-assistant`、`aud=ai-platform`、`sub=user_id`）。两侧对这三项的任何不一致都会导致**全链路 401**，因此 MUST 有互操作测试（见 [07-§3 `AC-TEST-01`](./07-验收标准与测试策略.md)）。

### 3.3 令牌校验顺序（网关中间件）

```text
① Authorization 头存在且为 "Bearer " 前缀
② 固定算法 HS256 验签
③ 校验 iss == "ai-assistant"
④ 校验 aud 含 "ai-platform"
⑤ 校验 exp / nbf（时钟偏移容差 ≤ 30s）
⑥ 校验 token_type == "access"
⑦ 校验 ver == 该用户当前 token_version（Redis 缓存 gw:user:ver:{user_id}，未命中查 MySQL）
⑧ 注入 user_id = sub 到请求上下文
```

任一步失败 MUST 返回 `401`，且响应 MUST NOT 泄漏具体失败原因（防探测）；但 `error.code` MAY 区分 `TOKEN_EXPIRED` 与 `UNAUTHENTICATED`，以便客户端触发静默刷新。

**性能要求**：② 为本地计算，⑦ 至多一次 Redis 读，总耗时 ≤ 3ms（P95）。

### 3.4 需求

| ID | 需求 |
| --- | --- |
| `REQ-AUTH-002` | 服务 MUST 按 §3.2 签发符合 `ai-platform` 校验要求的 Access Token，并提供互操作测试证明两侧一致。**本项是接缝 J1，不可简化** |
| `REQ-AUTH-003` | 刷新时 MUST 签发新的 Refresh Token 并作废旧的（单次有效）；已作废令牌再被使用 MUST 返回 `401 INVALID_REFRESH_TOKEN` |
| `REQ-AUTH-004` | 登出 MUST 作废该用户的 Refresh Token（`logout_all=true` 时作废其**全部** Refresh Token 并递增 `token_version`）。Access Token 不做服务端黑名单，依赖客户端丢弃 + `ver` 校验 |

## 4. 错误码

> 分两类：**网关自有**（AI 不产生）与**复用 AI 侧**（网关仅透传）。不要把 AI 的错误码改写成网关的（接缝 J2）。

### 4.1 网关自有错误码

| code | HTTP | retryable | message（zh-CN） | 触发条件 |
| --- | --- | --- | --- | --- |
| `INVALID_ARGUMENT` | 400 | 否 | 请求参数不合法 | 校验失败，`details.fields` 列出字段 |
| `UNAUTHENTICATED` | 401 | 否 | 身份未认证 | 缺 token / 签名错 / `ver` 不匹配 |
| `TOKEN_EXPIRED` | 401 | 否 | 登录已过期 | `exp` 过期；客户端**据此触发刷新** |
| `INVALID_CREDENTIALS` | 401 | 否 | 账号或密码错误 | 登录失败（与"用户不存在"同一码，防枚举） |
| `INVALID_REFRESH_TOKEN` | 401 | 否 | 刷新令牌无效 | 不存在 / 已作废 / 已过期 |
| `PERMISSION_DENIED` | 403 | 否 | 无权访问该资源 | 越权（**仅用于非资源存在性场景**；资源不存在一律 404） |
| `USER_DISABLED` | 403 | 否 | 账号已被禁用 | 用户状态非 `active` |
| `RESOURCE_NOT_FOUND` | 404 | 否 | 资源不存在 | 通用 404 |
| `CONVERSATION_NOT_FOUND` | 404 | 否 | 会话不存在 | `cv_id` 未知/越权/已删 |
| `MESSAGE_NOT_FOUND` | 404 | 否 | 消息不存在 | `msg_id` 未知/越权 |
| `CONFLICT` | 409 | 否 | 资源冲突 | 通用冲突 |
| `EMAIL_ALREADY_EXISTS` | 409 | 否 | 该邮箱已被注册 | 注册 |
| `CONVERSATION_ARCHIVED` | 409 | 否 | 会话已归档，不可发送消息 | 向归档会话发消息 |
| `PAYLOAD_TOO_LARGE` | 413 | 否 | 请求体过大 | 超过 `MAX_JSON_BODY_MB` |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | 否 | 不支持的内容类型 | Content-Type 不匹配 |
| `QUOTA_EXCEEDED` | 429 | 否 | 配额已用完 | 见 §5.2 |
| `RATE_LIMITED` | 429 | 是 | 请求过于频繁 | 见 §5.3，带 `retry_after` |
| `INTERNAL_ERROR` | 500 | 是 | 服务内部错误 | 未捕获异常 |
| `AI_UNAVAILABLE` | 503 | 是 | AI 服务暂时不可用，请稍后重试 | AI 侧不可达/熔断打开 |
| `AI_OVERLOADED` | 503 | 是 | AI 服务繁忙 | AI 侧返回 `OVERLOADED` |
| `DEPENDENCY_UNAVAILABLE` | 503 | 是 | 依赖服务不可用 | MySQL/Redis 不可用 |
| `AI_TIMEOUT` | 504 | 是 | AI 服务响应超时 | AI 侧调用超时 |

### 4.2 复用 `ai-platform` 的错误码（网关 MUST 原样透传）

| code | HTTP | 说明 |
| --- | --- | --- |
| `UPSTREAM_LLM_ERROR` / `UPSTREAM_LLM_AUTH_ERROR` | 502 | 模型服务异常 |
| `UPSTREAM_TIMEOUT` | 504 | 模型服务超时 |
| `CONTEXT_TOO_LONG` | 400 | 上下文超限 |
| `QUERY_EMPTY` | 400 | 提问为空 |
| `CONTENT_FILTERED` | 400 | 内容被拦截 |
| `KB_NOT_FOUND` / `DOCUMENT_NOT_FOUND` / `TASK_NOT_FOUND` / `MEMORY_NOT_FOUND` | 404 | AI 侧资源不存在 |
| `KB_NAME_CONFLICT` / `DOCUMENT_DUPLICATE` / `KB_NOT_EMPTY` / `TASK_NOT_CANCELABLE` / `TASK_NOT_RETRYABLE` | 409 | AI 侧冲突 |
| `FILE_TOO_LARGE` / `UNSUPPORTED_FILE_TYPE` | 413 / 415 | 上传校验（**网关侧 SHOULD 提前拦截同规则**，避免无谓转发） |
| `UNPROCESSABLE_DOCUMENT` | 422 | 文档无法解析 |
| `TOOL_NOT_FOUND` / `TOOL_FORBIDDEN` / `TOOL_EXECUTION_FAILED` / `TOOL_TIMEOUT` | 404/403/502/504 | 工具相关 |
| `MCP_SERVER_NOT_FOUND` / `MCP_SERVER_UNAVAILABLE` / `UPSTREAM_MCP_ERROR` | 404/503/502 | MCP 相关 |
| `RETRIEVAL_FAILED` | 503 | 检索失败 |
| `OVERLOADED` | 503 | AI 侧过载 |
| `DEPENDENCY_UNAVAILABLE` | 503 | AI 侧依赖不可用 |
| `SUMMARY_UNAVAILABLE` / `SUMMARY_GENERATION_FAILED` | 404 / 502 | 摘要相关 |

**透传规则（MUST）**：

1. 保留 `error.code`、`error.message`、`error.details`、`error.retryable` 原值。
2. 保留 `error.trace_id`（**不是**替换成网关自己的 request id）——否则排障时链路断裂。
3. 保留 HTTP 状态码原值。
4. 网关 MAY 在 `details` 中**追加** `gateway` 对象（如 `{"gateway":{"upstream":"ai-platform"}}`），但 **MUST NOT 修改或删除原有键**。
5. 若 AI 侧返回非约定格式（如 502 网关错误页），网关 MUST 归一化为 `AI_UNAVAILABLE` / `AI_TIMEOUT`，并把原始状态码放入 `details.upstream_status`。

## 5. 配额与限流

### 5.1 配额维度

| 指标 (`metric`) | 单位 | 默认（免费档） | 说明 |
| --- | --- | --- | --- |
| `chat_requests` | 次 | 100 / 天 | 对话请求数（含流式） |
| `llm_tokens` | token | 200000 / 天 | 按 AI 上报 `usage.total_tokens` 累计 |
| `kb_count` | 个 | 3 | 知识库数量（上限，非按天） |
| `documents_count` | 个 | 50 | 文档数量（上限） |
| `storage_bytes` | 字节 | 536870912（512MB） | 已上传原始文件总量 |
| `concurrency` | 路 | 5 | **并发**对话数（瞬时，非累计） |

- 周期定义：`chat_requests` / `llm_tokens` 为**自然日**（`QUOTA_TIMEZONE`，默认 `Asia/Shanghai`），`reset_at` 为次日 00:00。
- `kb_count` / `documents_count` / `storage_bytes` 为**存量上限**，删除资源后释放。
- 配额值可由用户档位（`plan`）决定，MUST NOT 硬编码在代码里。

### 5.2 扣减语义（接缝 J7）

```text
请求进入
  ↓
① 读配额（Redis gw:quota:{user}:{metric}:{period}，未命中回源 MySQL）
② 校验是否足额 → 不足则 429 QUOTA_EXCEEDED（details 带 limit/used/reset_at），**不调用 AI**
③ 预扣：chat_requests += 1（原子 INCR，带周期 TTL）
④ 调用 AI
  ↓ 成功且拿到 usage
⑤ 按 usage.total_tokens 累加 llm_tokens（实际值）
  ↓ 失败（无 usage）
⑥ 回滚第 ③ 步的 chat_requests（仅当失败原因为网关/AI 内部错误，而非参数错误）
```

| 规则 | 说明 |
| --- | --- |
| 预扣 | MUST 在调用 AI **之前**完成，防并发绕过（用 Redis `INCR` 原子性） |
| 回滚 | 仅对 `AI_UNAVAILABLE` / `AI_TIMEOUT` / `INTERNAL_ERROR` / 熔断拒绝回滚；**参数错误与内容过滤不回滚**（避免滥用） |
| 异步对账 | 每 5 分钟把 Redis 计数快照写入 MySQL `quota_usage`，防 Redis 丢失导致用量不可查 |
| 权威性 | 每日 0 点以 MySQL 为准重建 Redis 计数（Redis 是加速器，不是唯一真源） |
| 并发配额 | `concurrency` 用 Redis 计数器 + 请求结束/断开时 `DECR`（MUST 在 defer 中保证释放） |
| 只读不写 | `ai-platform` **MUST NOT** 扣减配额，只上报 `usage`（否则双重扣减） |

### 5.3 限流（`REQ-AUTH-008`）

| 维度 | 默认阈值 | 超限 |
| --- | --- | --- |
| 单 IP 登录尝试 | 10 次 / 分钟 | `429 RATE_LIMITED` |
| 单用户会话创建 | 30 次 / 分钟 | `429` |
| 单用户消息发送 | 20 次 / 分钟 | `429` |
| 单用户文档上传 | 10 次 / 分钟 | `429` |
| 单用户并发对话 | 5（= 配额 `concurrency`） | 排队 3s，仍满则 `429 RATE_LIMITED` |
| 全局入站 QPS | `GLOBAL_QPS_LIMIT`（默认 500） | `503 AI_OVERLOADED` |

实现：Redis 令牌桶 / 滑动窗口（`gw:rate:{scope}:{id}`），响应 MUST 带 `Retry-After`（秒）。限流拒绝 MUST 记指标 `gw_rate_limited_total{scope}`。

### 5.4 需求

| ID | 需求 |
| --- | --- |
| `REQ-AUTH-006` | 服务 MUST 在调用 AI 之前完成配额校验与预扣，配额不足时 MUST NOT 产生对 `ai-platform` 的调用 |
| `REQ-AUTH-007` | 服务 MUST 提供用量查询接口，返回各 metric 的 `limit`/`used`/`remaining`/`reset_at` 及近 N 日明细 |
| `REQ-AUTH-008` | 服务 MUST 实现 §5.3 的多维限流，且 MUST NOT 因限流器故障而放行全部请求（Redis 不可用时按本地兜底限额降级，并记告警） |

### 6.3 需求

| ID | 需求 |
| --- | --- |
| `REQ-AUTH-001` | 注册 MUST 用 Argon2id 哈希密码（`memory=64MB`、`iterations=3`、`parallelism=4`，参数可配置），并 MUST 校验密码强度下限（长度 ≥ 8、非常见弱口令） |
| `REQ-AUTH-005` | `GET /me` MUST 只返回当前 JWT 对应的用户，且 MUST NOT 返回密码哈希、`token_version`、内部状态字段 |
| `REQ-AUTH-009` | 生产环境 MUST 仅接受 HTTPS；HTTP 请求 MUST 301 到 HTTPS（或由前置 LB 终止并强制） |
| `REQ-AUTH-010` | 所有列表接口 MUST 使用游标分页，`limit` 超上限返回 `INVALID_ARGUMENT` 而非静默截断 |

## 7. 幂等

| 接口 | 幂等机制 |
| --- | --- |
| `POST /auth/register` | 自然幂等：同邮箱返回 `409 EMAIL_ALREADY_EXISTS` |
| `POST /auth/refresh` | **非幂等**：每次返回新 refresh（旧的立即作废）。客户端 MUST 串行化刷新；并发刷新导致旧令牌被误用时返回 401，重新登录即可 |
| `POST /conversations` | 支持 `Idempotency-Key`，24h 内同键返回同一会话 |
| `POST /conversations/{id}/messages` | 支持 `Idempotency-Key`，防「重试导致重复提问」 |
| 上传文档 | 透传 `Idempotency-Key` 给 AI 侧（AI 侧据此返回同一 `task_id`） |
| `DELETE *` | 幂等；删除不存在资源返回 `404`（不返回 204，避免掩盖越权） |
| 其它 `POST`（如 `/logout`） | 幂等：重复登出返回 204 |

`Idempotency-Key` 建议 UUID；服务端以 `(user_id, method, path, key)` 为唯一键，命中则回放首次响应（含状态码）。存储表见 [05-§2.7](./05-数据模型.md)。

## 8. 验收标准

| ID | 关联需求 | 验收点 |
| --- | --- | --- |
| `AC-AUTH-01` | `REQ-AUTH-001` | 注册后 MySQL 中 `password_hash` 以 `$argon2id$` 开头；用弱口令（`12345678`）注册返回 400 |
| `AC-AUTH-02` | `REQ-AUTH-002` | 解码登录返回的 access_token：`iss=ai-assistant`、`aud=ai-platform`、`sub` 为 `u_*`、含 `ver`/`token_type=access` |
| `AC-AUTH-03` | `REQ-AUTH-002` | 把 `aud` 改成 `ai-assistant` 后重新签发 → `ai-platform` 返回 `401 UNAUTHENTICATED`（证明该字段是硬约束，且互操作测试能抓到） |
| `AC-AUTH-04` | `REQ-AUTH-003` | 用同一 refresh 连续刷新两次 → 第二次返回 `401 INVALID_REFRESH_TOKEN`（旧令牌已作废） |
| `AC-AUTH-05` | `REQ-AUTH-004` | 登出后用原 refresh 刷新 → 401；`logout_all=true` 后旧 access 因 `ver` 不匹配 → 401 |
| `AC-AUTH-06` | `REQ-AUTH-006` | 把 `chat_requests` 限额改为 1，发第 2 次对话 → `429 QUOTA_EXCEEDED`，且 `ai-platform` 侧**未收到**任何调用（查其访问日志） |
| `AC-AUTH-07` | `REQ-AUTH-006` | 让 AI 返回 `503`，观察配额：`chat_requests` 回滚为原值；再让 AI 返回 `400 QUERY_EMPTY`，观察配额**未**回滚 |
| `AC-AUTH-08` | `REQ-AUTH-008` | 1 分钟内第 11 次登录尝试返回 `429`，且响应带 `Retry-After`；用另一 IP 请求正常 |
| `AC-AUTH-09` | `REQ-AUTH-005` | `GET /me` 响应 JSON 中不含 `password` / `token_version` / `hash` 任一子串 |
| `AC-AUTH-10` | `REQ-AUTH-010` | `limit=101` 返回 400；造 55 条会话翻 3 页，三页 ID 并集无重复无遗漏 |
