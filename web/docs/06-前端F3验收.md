## 实现

### 传输

- `fetch + ReadableStream`，不用 `EventSource`（接口是 POST 且必须带 Authorization）。
- `eventsource-parser` v4 解析 `event:` / `data:`；所有帧运行时归一到 `ChatEvent`。
- 401 只在 `TOKEN_EXPIRED` 时 `refreshOnce()` 并重放一次；其它 401 直接进错误卡。
- 支持事件：

```text
meta / reference / token / tool_call / tool_result / usage / done / error
gw_persist_error / ping / 未知事件（忽略）
```

### 状态机

- `idle → connecting → streaming → done | aborted | error`
- token 50ms 批量刷新，避免每个 token 一次 React render；
- 45s 无帧看门狗 → `STREAM_IDLE_TIMEOUT`；
- `stop()` 走 `AbortController`，服务端把已生成内容写成 `partial`；
- `done/error/abort` 结束后统一 `refetch` messages + conversation：
  - 不依赖 `meta` 里的用户消息 ID（B-05 后置）；
  - 以台账为准，刷新后能看到真实的用户消息与 `partial`；
  - 历史助手消息 ID 与 `meta.message_id` 对齐后，live turn 收起，避免双份。

### 渲染

- 助手正文 `react-markdown + remark-gfm + rehype-sanitize`；
- `[n]` 预处理成 `#ref-n` 链接，自定义 `a` 渲染器换成可点击角标；
- 引用资料卡：`doc_name / 标题路径 / 页码 / score / snippet`，点击角标展开并滚动到卡片；
- 工具轨迹：`tool_call` 先占位 running，`tool_result` 覆盖状态/摘要/耗时；历史消息同样可展开；
- 错误卡：`code / message / retryable / trace_id`；
- 降级：`degraded` chip；`gw_persist_error` 显示“保存失败”警告。

## 浏览器验收

```powershell
cd web
pnpm e2e:f3
```

结果：`PASS`

1. 登录 → 打开 `F3 流式验收` 会话；
2. 发送约一千字长文请求，等待首个 token；
3. 350ms 后再采样，正文长度增长（真实逐字流）；
4. 点停止 → live `partial` → 服务端落库 → 历史出现 `partial`；
   停止后首次 refetch 可能早于 partial 落库，前端每 250ms 重拉一次（最多 12 次），
   直到 assistant 出现在台账，live 才收起；
5. 刷新 → `partial` 与正文仍在；StrictMode 下首轮历史恰好 **2 条**（用户 + partial）；
6. 第二轮短问题 → `done`，发送键恢复，历史恰好 **4 条**（无重复发送），无 `stream-error`。

## 边界

- 一个会话同时只允许一条流；发送中不能再次发送，必须先停止。
- 离开会话页会 abort 当前流（F3 不做后台续传）；断线/多标签恢复留到后续。
- 停止后的 `usage` 可能为 0，这是取消时尚未收到 usage 帧，不是前端丢数据。
- 引用/工具 UI 用注入数据验证；真实知识库、真实工具调用的端到端验收在 F4。
- 没有做“重新生成/编辑用户消息”；F5/F6 再评估。
