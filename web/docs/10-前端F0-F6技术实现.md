## 0. 全局结构

```text
src/
├─ app/                 # Router、QueryClient、AppLayout、页面 fallback
├─ features/
│  ├─ auth/             # 登录/注册/启动恢复
│  ├─ conversations/    # 会话列表、详情、搜索
│  ├─ messages/         # 消息分页、删除、重新生成、增量刷新
│  ├─ chat/             # 聊天页、流式状态机、Markdown/引用/工具
│  ├─ knowledge/        # KB、文档、切片、检索、上传
│  ├─ tasks/            # 任务列表、轮询/SSE、取消/重试
│  ├─ memory/           # 长期记忆、设置
│  ├─ quota/            # 配额与用量
│  └─ settings/         # 资料、安全、主题
└─ shared/
   ├─ api/              # base/client/error/session/rate-limit/types
   ├─ lib/              # 时间格式化等纯函数
   └─ ui/               # Icon/Modal/Markdown/toast/RateLimitBanner
```

依赖方向固定：

```text
routes/app → features → shared
```

- `features` 不互相 import 页面组件；跨 feature 只复用 `api/types/queries`。
- `shared` 不知道业务 feature；`app` 只做装配、布局和路由。
- Router 用 `lazy()` 做路由级拆包；`ConversationPage/KnowledgePage/TasksPage/MemoryPage/QuotaPage/SettingsPage` 都是独立 chunk。

## 1. F0 脚手架

### 1.1 实现内容

- Vite + React 19 + TypeScript + Tailwind v4；
- TanStack Router（文件路由 + 类型安全参数）；
- TanStack Query（服务端状态）；
- Zustand（登录态、流式 turn、UI 偏好）；
- 设计令牌、应用壳、登录壳、`PageFallback`；
- `shared/api` 基础封装：`API_BASE`、`apiRequest`、错误信封。

### 1.2 关键文件

| 文件 | 职责 |
| --- | --- |
| `src/main.tsx` | 挂载 Router/Query/Toaster，导入全局样式 |
| `src/app/router.tsx` | 路由树、懒加载、根重定向 `/ → /chat` |
| `src/app/AppLayout.tsx` | 侧栏、顶栏、移动端抽屉、⌘K、全局 toast |
| `src/app/query-client.ts` | staleTime/gcTime/retry 策略 |
| `src/shared/api/client.ts` | fetch 封装、Bearer、401 refresh 重放、429 |
| `src/shared/api/base.ts` | `VITE_API_BASE_URL`，默认 `/api/v1` |

### 1.3 Query 默认策略

- `staleTime: 30s`；`gcTime: 5min`；
- `refetchOnWindowFocus: false`：多标签/焦点刷新由显式增量刷新处理，避免页面聚焦时整页重拉；
- 查询重试：只对 `5xx`/`NETWORK` 重试，最多 2 次；`4xx` 不重试（429/配额重试会放大问题）；
- mutation 不自动重试。

### 1.4 技术取舍

- 不做 SSR/Next：所有页面登录后可见，SEO 无收益；SSE/内存 token 与 SSR 不匹配。
- 不做全局状态库：只有登录态和流式 turn 需要跨组件，Query 负责服务端状态。

## 2. F1 登录与启动恢复

### 2.1 状态机

`useAuthStore.status` 只有三态：

```text
booting ──refresh成功+/me成功──> authed
   │
   └─refresh失败/无Cookie────────> anonymous
```

- `bootstrap()` 用模块级 `bootstrapPromise` 防止 StrictMode/多组件重复执行；
- 启动时**无条件** `refreshOnce()`：refresh 在 HttpOnly Cookie 中，JS 无法判断是否存在；
- refresh 成功后 `/me`；失败则匿名；
- `auth:expired` 事件由 `clearSession(true)` 触发，store 监听后置匿名。

### 2.2 access / refresh

| 项 | 实现 |
| --- | --- |
| access | 只在 `shared/api/session.ts` 的模块变量中，不落 localStorage |
| refresh | 服务端 HttpOnly `ai_refresh` Cookie，JS 不可读 |
| 并发刷新 | `refreshInflight` 单飞 + 可用时 `navigator.locks.request("auth:refresh")` |
| 401 重放 | `apiRequest` 对 `TOKEN_EXPIRED` 只刷新并重放一次 |
| 退出 | access 缺失时先 refresh 再调 `/auth/logout`，最后本地清理 |

`setSession` 只写 access；`clearSession` 清 access 并顺手删除旧版本遗留的 `ai.refresh.v1`（迁移清理，不是当前存储）。

### 2.3 登录/注册

- 登录：`POST /auth/login`，响应 `TokenResponse` 只含 access + user；
- 注册：`POST /auth/register` 可能只返回 user；若响应无 access，自动再登录一次；
- 登录后 `setSession`，user 优先用响应里的，否则 `/me`；
- 登录页错误直接展示 `ApiError.code + message`，字段错误由后端 `details.fields[]` 支撑。

## 3. F2 会话与历史

### 3.1 会话列表

- `useConversationList` 使用 `useInfiniteQuery`；
- 游标：`next_cursor`，前端不推算 offset；
- 20/页，侧栏滚动加载；
- query key：`["conversations","list",filters]`；
- 侧栏搜索输入 280ms 防抖；标题命中用 `keyword` 查询。

### 3.2 会话详情/消息

- `useConversation(id)`：详情 query，key `["conversations","detail",id]`；
- `useMessages(id)`：`useInfiniteQuery`，`order=desc`，30/页；
- 页面把 pages 展平、按 `id` 去重，再按服务端 seq 语义渲染；
- 消息列表按 seq 排序；历史加载保持滚动位置；
- 归档会话：输入框禁用，顶部提示。

### 3.3 写操作与失效

| 操作 | 失效 |
| --- | --- |
| 新建/改名/置顶/归档/删除 | `["conversations"]` 全前缀 |
| 发消息完成/停止 | messages + detail + list |
| 删除消息 | `["conversations"]` 全前缀（含 context/summary） |
| 重新生成 | `["conversations"]` 全前缀 |

统一用前缀失效，避免漏掉 detail/messages/context/list 中的某一个。

### 3.4 侧栏消息命中（B-10）

- 输入关键词时同时请求：
  - `GET /conversations?keyword=`（标题/会话）；
  - `GET /search/messages?q=`（消息正文）；
- 消息命中显示会话标题 + snippet，点击打开对应会话；
- 搜索 query 独立 key：`["conversations","search",keyword]`，5s stale。

## 4. F3 流式对话

### 4.1 五层拆分

```text
stream.ts        fetch + ReadableStream + SSE 帧
   ↓ ChatEvent
parse.ts         帧类型/字段 → 判别联合
   ↓
reducer.ts       TurnState 状态机
   ↓
useChatStream    发送/停止/超时/对账
   ↓
LiveTurn/ConversationPage 渲染
```

### 4.2 传输层 `stream.ts`

- `POST /conversations/{id}/messages/stream`；
- 必须 `fetch`：POST + `Authorization`，`EventSource` 不支持；
- 请求头：`Accept: text/event-stream`、`X-Request-Id`、Bearer；
- 401 且 `TOKEN_EXPIRED`：`refreshOnce()` 后重放一次；
- 用 `eventsource-parser` 解析：处理 CRLF/LF、多行 data、BOM、半 UTF-8 chunk；
- 非 2xx 走统一 `ApiError`；429 记录 `retry_after`。

### 4.3 事件与状态 `parse.ts` / `reducer.ts`

事件：

```text
meta → reference* → token* → tool_call/tool_result* → usage → done
                                                ↘ error
```

- `meta`：conversation_id/message_id/user_message_id/user_seq/model/degraded；
- `reference`：整组覆盖（不是追加），保证 `[n]` 编号稳定；
- `token`：增量拼接；
- `tool_call`/`tool_result`：按 `call_id` 合并，未配对标记；
- `usage`：记录 token；
- `done`：finish_reason/elapsed/partial；
- `error`：code/message/retryable；
- `gw_persist_error`：正文已完成但落库失败；
- 未知事件保留并透传，不中断。

`TurnState` 字段：phase、userText、assistantId、model、content、references、tools、usage、finishReason、partial、elapsedMs、degraded、error、persistError、startedAt。

### 4.4 控制器 `useChatStream.ts`

- 一次只允许一条流：`controllerRef` 非空时拒绝再次发送；
- token 50ms 批量 flush，降低高频重渲染；
- 首帧前失败：`streamChat` 抛错 → error 卡；
- 45s 看门狗：超过 45s 无事件 → `timeout` + abort；
- 用户 stop：`abort`，保留已收到 content；
- 流结束但没有 `done`：`STREAM_CLOSED`；
- 结束后 `finally` 调 `onSettled` → messages/detail/list 对账。

### 4.5 停止与 partial 对账

停止后服务端落 partial 可能晚于第一次 refetch。`ConversationPage`：

1. 先 refetch；
2. 若 `phase=aborted/done` 且 `assistantId` 还不在台账 → 250ms 轮询，最多 12 次；
3. assistant 出现后 `assistantPersisted=true`，live 收起。

### 4.6 UI

- `LiveTurn`：user 文本、assistant 正文、tool trace、引用、usage/elapsed、partial/degraded 标记；
- Markdown：`react-markdown + remark-gfm + remark-math + rehype-katex + rehype-sanitize`；支持 `$...$` / `$$...$$`，引用 `[n]` 映射到资料卡；
- `ReferenceDetails`：引用列表、评分条、“查看原文”（B-02）；
- `StreamErrorCard`：code/message/retryable + 建议动作（F6）；
- 历史消息复用同一套 Markdown/引用/工具组件。

## 5. F4 知识库与任务

### 5.1 知识库

- `useKnowledgeBases` 无限列表；
- 选中 KB 后：文档列表、切片、检索、上传；
- 文档状态：`PENDING → PARSING → CHUNKING → EMBEDDING → INDEXED`，失败 `FAILED`，删除 `DELETING`；
- 写操作统一失效 `["knowledge"]` + `["tasks"]`。

### 5.2 上传

- 用 XHR（`XMLHttpRequest.upload.onprogress`）而非 fetch：需要真实上传进度；
- `POST /knowledge-bases/{id}/documents`，`FormData` 字段 `file`；
- 进度条 + 取消；202 后进入任务轮询；
- 上传横幅按文档终态显示“已入库/入库失败”，可关闭。

### 5.3 任务

- `useTasks` 无限列表，2s 轮询；
- 有活跃任务（PENDING/QUEUED/RUNNING）才轮询，终态停止；
- B-01 起优先订阅 `GET /tasks/{id}/events`：
  - `streamTaskEvents` 用 fetch + Bearer；
  - 收到事件即失效任务查询；
  - SSE 失败/结束保留轮询兜底。
- 任务操作：取消、失败重试；`cancel_requested` 显示“取消中…”；
- 知识库页的“入库任务”按当前 KB 的文档 ID 过滤，不按 KB ID。

### 5.4 切片与检索

- 文档详情抽屉：分页切片；
- 检索测试：query + top_k，展示命中分数/内容；
- 只允许对 `INDEXED` 文档做切片/检索。

## 6. F5 记忆、配额、设置、透视

### 6.1 记忆

- `useMemories` 分页 + 筛选项；
- 新建/编辑/删除/settings 分开 mutation；
- 设置开关本地 dirty 标记：保存期间不被后台 refetch 覆盖；
- 清空记忆二次确认；
- 失败保留当前列表，不乐观删除。

### 6.2 配额

- `/me/quota` + `/me/usage` 两个 query；
- 6 维配额卡：chat_requests/llm_tokens/kb_count/documents_count/storage_bytes/concurrency；
- 用量图按日聚合；
- 429 不重试；显示 `retry_after` 倒计时。

### 6.3 记忆/配额与 429 的交互

- `shared/api/rate-limit.ts` 是 Zustand store；
- 429 时 `markRateLimited(retryAfter)`，`RateLimitBanner` 每秒倒计时；
- B-07 起同时读取 `X-RateLimit-*`，`scope=message` 时提前显示剩余次数，0 时禁用发送；
- 倒计时结束 `clear()`，恢复发送。

### 6.4 资料与安全

- 资料：昵称/邮箱展示；
- 改密：旧密码/新密码，成功后服务端清 refresh Cookie，前端强制重新登录；
- 主题：`data-theme=light/dark` 写 localStorage，CSS 变量切换；
- 退出：清理 access + store，跳 `/login`。

### 6.5 上下文透视

- `GET /conversations/{id}/context`、`/summary`；
- 展示预算、已用 tokens、裁剪项、摘要、消息；
- 可重建摘要（`POST /summary/rebuild`）；
- 只读诊断，不直接改上下文。

## 7. F6 质量收口

### 7.1 键盘与焦点

`Modal`：

- `role=dialog` + `aria-modal` + `aria-labelledby`；
- 打开时焦点进入第一个可聚焦控件；
- Tab/Shift+Tab 在对话框内循环；
- Esc 关闭；
- 关闭恢复打开前焦点；
- 锁定 body 滚动，卸载恢复。

全局：⌘K/Ctrl+K 聚焦会话搜索；Enter 发送、Shift+Enter 换行。

### 7.2 错误动作

`shared/api/error-actions.ts` 把错误码映射到建议动作：

- `TOKEN_EXPIRED` → 重新登录；
- `RATE_LIMITED` → 等待倒计时；
- `QUOTA_EXCEEDED` → 查看配额；
- `CONVERSATION_ARCHIVED` → 取消归档；
- `AI_UNAVAILABLE/AI_TIMEOUT/...` → 稍后重试；
- 未知码 → “无自动动作”。

`StreamErrorCard` 展示“建议：…”，但不自动重试。

## 8. 跨阶段约定

### 8.1 错误

- 所有 HTTP 错误归一为 `ApiError`（code/message/status/details/traceId/retryable/retryAfter）；
- UI 不拼后端文案，只展示 + 给动作；
- 401 只在 `apiRequest` 内刷新重放一次，避免递归。

### 8.2 缓存失效

| 前缀 | 覆盖 |
| --- | --- |
| `["conversations"]` | list/detail/messages/search/context/summary |
| `["knowledge"]` | kb/documents/chunks |
| `["tasks"]` | 任务列表/轮询 |
| `["memories"]` | 记忆列表/设置 |

### 8.3 测试分层

- `pnpm typecheck` + `pnpm build`：类型/打包；
- `pnpm e2e:fN`：真实浏览器 + 真实网关；
- 失败时截图在 `web/previews/`；
- E2E 先探测 `/health`，失败信息指向环境而非 UI。

## 9. 已知边界

- 流式没有自动重连；断线以台账 refetch/手动增量刷新为准；
- B-09 附件只支持已入库文档 ID，不支持二进制直传；
- B-10 搜索是 LIKE 版，未接 FULLTEXT/embedding；
- 任务 SSE 失败自动回退轮询，不保证 SSE 全程可用；
- 移动端最小验收 500px，未覆盖 390px 真机。
