## 实现

### 长期记忆

- 记忆设置：`memory_enabled` / `memory_top_n`，保存期间用 dirty 标记保护本地编辑；
- 手动记忆：新增（偏好/事实/置信度）、编辑、删除、分页；
- `DELETE /memories?all=true` 清空前二次确认；
- 关闭记忆时禁止新增/清空，提示“模型不会召回或写入”；
- 记忆自动抽取由对话触发；F5 用 `use_memory=true` 的对话验证。

### 配额与用量

- `GET /me/quota`：6 个指标（对话请求、LLM tokens、知识库、文档、存储、并发）；
- `GET /me/usage`：本周期明细与 `chat_requests / llm_tokens` 汇总；
- 指标卡显示 used/limit/remaining、进度、`reset_at`；
- 用尽时显示“已用尽 + 重置时间”，不自动重试；
- 全局 429：`apiRequest`/流式请求收到 429 后写 rate-limit store，顶栏显示倒计时，
  对话发送按钮禁用；倒计时结束自动恢复。

### 上下文透视 / KB 关联

- 会话头新增“知识库 N”：多选 KB（最多 10 个），`PATCH /conversations/{id}` 的 `kb_ids`；
- “上下文”弹窗：token 预算、used/trimmed 分片、摘要状态与内容、上下文消息；
- “重建摘要”走 `POST /summary/rebuild`，返回 task_id；
- “清空上下文”二次确认，只清本会话上下文，不删消息/长期记忆。

### 设置

- 改密：旧密码 + 新密码 + 确认；成功后清本地会话并跳登录；
- 主题：亮/暗写入 `localStorage`，刷新保持。

### 429 定向测试

单独把网关以 `MSG_RATE_PER_MINUTE=1` 启动，同一账号连发两条：

- 第二条返回 `RATE_LIMITED`；
- 顶栏出现“请求过快 / 61s”，发送按钮禁用；
- 错误卡显示 `RATE_LIMITED` 与 trace_id；
- 空内容错误不再渲染“生成失败” live 占位；
- 侧栏同步为“2 条消息 · 刚刚”。

## 边界

- 记忆过期时间未做编辑 UI；接口支持 `expires_at`，F6 可补。
- 摘要未生成时只显示“尚未生成”；重建是异步任务，不等生成完成。
- 429 的倒计时来自 `Retry-After`，不是配额 `reset_at`；配额耗尽的恢复时间看指标卡。
- B-15 后关闭记忆仍保留短期上下文；长期记忆召回/抽取才受开关控制。
- Docker Redis 已就绪，配额 `used` 与 usage 明细一致（I-18 已解决）。
