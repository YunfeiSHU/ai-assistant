## 实现

### 知识库

- KB 列表/创建/删除；创建时校验 `chunk_overlap < chunk_size`、`rerank_top_n ≤ top_k`；
- 文档上传用 **XHR**（需要 `upload.onprogress`，fetch 拿不到上传进度）：
  - `Authorization`、`X-Request-Id`、`Idempotency-Key`；
  - 单文件前端限制 50MB；202 后进入任务，不阻塞页面；
  - `TOKEN_EXPIRED` 时刷新并重放一次。
- 文档列表每 2s 轮询，`INDEXED / FAILED / DELETED` 等终态停止；
- 文档切片：分页查看 `chunk_index / tokens / heading / page / content`；
- 检索调试：`top_k / rerank_top_n / score_threshold / with_rerank`，展示召回数、返回数、
  rerank 是否启用、耗时，以及 `vector_score / rerank_score`。

### 任务

- 任务列表按 `status` 过滤：全部 / 运行中 / 排队 / 失败 / 已完成 / 已取消；
- 有 `PENDING/QUEUED/RUNNING` 时每 2s 轮询，全部终态后停止；
- `cancelable` 显示取消、`retryable` 显示重试；
- 失败任务显示 `error.code`，重试后重新入队；
- 知识库页的入库任务按当前 KB 的文档 ID 过滤（任务 `resource_id` 是文档 ID，不是 KB ID）。

## 浏览器验收

```powershell
cd web
pnpm e2e:f4
```

结果：`PASS`

1. 登录 → 知识库 → 新建「F4 验收库」；
2. 上传 `refund.md`（2.4KB）→ 上传进度 → 状态从 `PENDING/RUNNING` 到 `INDEXED`；
3. 打开切片 → 正文包含退款政策；
4. 检索「退款多久到账」→ 召回 2、返回 1、rerank ≈229ms，命中退款文本；
5. 任务中心 → 文档入库任务 `SUCCEEDED`，分片 2/2；
6. 上传过短 `bad.txt` → 文档 `FAILED/UNPROCESSABLE_DOCUMENT`；
7. 任务中心点重试 → 收到 `202`/200 并重新入队，出现“已重新入队”。

## 边界

- KB 支持创建/删除；参数编辑（改名、chunk 调整）暂未做 UI，接口已存在。
- 上传只支持单文件；不支持文件夹/多选批量。
- 不做文档原文下载/预览（B-02）；引用回原文仍缺能力。
- 任务无详情抽屉；错误码在列表内可见，完整 `detail` 需后续补。
- 检索调试独立于聊天；F5 才把 KB/记忆/上下文预算接进对话。
- 20MB 是 API 容量验证；浏览器 E2E 用小文件验证进度与状态流转。
