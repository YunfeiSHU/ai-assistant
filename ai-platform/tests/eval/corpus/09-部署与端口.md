# 部署与端口

## 本地编排

本地基础设施通过 Docker Compose 一键拉起，包含 Redis、MySQL、Milvus、MinIO、Jaeger、Prometheus 与 Grafana。
可观测栈单独一份 Compose 文件，因为多数本地开发并不需要看板。

## 端口分配

主应用监听 8000；指标走独立端口 9105，主应用不暴露 /metrics。
gRPC 服务监听 50051，默认关闭。网关监听 18085（验收脚本会用到 18085 与 18086 两个实例）。
Milvus 监听 19530，MinIO 监听 9005，Jaeger 的 OTLP 端口是 4317。

## 依赖管理

Python 侧使用 uv 管理依赖，锁文件为 uv.lock，可选依赖按 extra 安装：redis、kafka、mysql、minio。
Go 侧使用 go modules，工具链版本固定在 go.mod 中，不要随意上调该版本。

## 部署目标

设计目标是 Kubernetes 的水平扩展部署，但仓库内并未提供任何 Kubernetes 清单。
因此当前的部署形态只有 Docker Compose，Kubernetes 仍属于规划。

## 配置来源

配置唯一来源是 .env 加环境变量，启动时做校验。
配置文件路径由 ENV_FILE 指定为绝对路径，避免工作目录不同导致读到不同的配置。
