# 多租户与数据隔离

## 权威属主

每份数据只有一个权威属主，另一方只能透传，禁止双写。
用户、凭据、刷新令牌、会话、消息台账、配额与用量的属主是 Go 网关。
对话摘要、短期上下文、长期记忆、知识库与文档元数据、AI 任务的属主是 Python 服务。

## 向量层隔离

向量库通过 user_id 标量字段做过滤，并在该字段上建立倒排索引。
检索请求必须携带 user_id，缺失时直接拒绝，而不是退化为全库检索。

## Redis 键空间划分

两个服务共用同一个 Redis 实例，因此键前缀必须隔离。
网关所有键以 gw: 开头；Python 侧使用 ctx:、lock:、summary:、task:、cancel:、embed:、dedupe:、rate: 等前缀。
前缀撞了就是互相覆盖，因此新增前缀必须先在文档中登记。

## 共享表

idempotency_record 与 audit_log 是两侧共享的表，同一个库里只能有一份定义。
网关侧不得再 CREATE 一遍：两个 CREATE 中第二个会因「表已存在」而看起来成功，实际用的是先建好的那张。
